## Ön/Arka Uç Ayrımıyla Geliştirmeye Giriş

> **Translated to Turkish by** himmetcanumutlu

Geleneksel Web uygulama geliştirmede çoğu programcı tarayıcıyı ön/arka ucun sınır çizgisi olarak alır. Tarayıcıda kullanıcıya sayfa gösterimi yapan kısma ön uç; sunucuda çalışıp ön uca iş mantığı ve veri hazırlığı sağlayan tüm koda arka uç denir. Ön/arka uç ayrımıyla geliştirme, ön ve arka uç mühendislerinin veri alışveriş arayüzünü kararlaştırıp paralel geliştirme ve test yapmasıdır; arka uç yalnızca veri sağlar, veriyi sayfaya render etmekle yükümlü değildir; ön uç HTTP isteğiyle veriyi alıp sayfaya render etmekten sorumludur; bu iş tarayıcıdaki JavaScript koduna bırakılır.

Ön/arka uç ayrımıyla geliştirmenin birçok faydası vardır; kısaca söyleyelim:

1. **Geliştirme verimliliğini artırır**. Ön/arka uç ayrıldıktan sonra ön ve arka uç kodunun bağı çözülür; uygulamanın ihtiyaç duyduğu arayüzleri ve arayüz parametrelerini kararlaştırdıktan sonra paralel geliştirme başlayabilir; karşı tarafın geliştirmesinin bitmesini beklemek gerekmez. Bu durumda ön ve arka uç mühendisleri yalnızca kendi işlerine odaklanabilir; daha iyi bir ekip kurulmasına yardımcı olur. Ayrıca ön/arka uç ayrımı geliştirme modelinde, gereksinim değişse bile arayüz ve veri biçimi değişmediği sürece arka uç geliştiricinin kodu değiştirmesi gerekmez; yalnızca ön uç değişir.
2. **Kodun bakım kolaylığını artırır**. Ön/arka uç ayrıldıktan sonra uygulamanın kodu artık ön ve arka uç karışık değildir; yalnızca çalışma anında çağrı bağımlılığı olur; böylece kod bakımı çok daha rahat olur; bir yere dokununca her şey bozulmaz. Kodunuz sade ve düzenli olduğunda, kodun okunabilirliği ve bakım kolaylığı niteliksel olarak artar.
3. **Çoklu terminal ve servis mimarisini destekler**. Ön/arka uç ayrıldıktan sonra aynı veri arayüzü farklı terminallere hizmet verebilir; çoklu terminal uygulaması kurmaya yardımcı olur; ayrıca arka ucun sunduğu arayüzler HTTP(S) ile çağrılabildiğinden servis mimarisi (mikro servis dahil) kurmaya yardımcı olur.

Şimdi ön/arka uç ayrımı yöntemiyle önceki oylama uygulamasını yeniden yazalım.

### JSON Biçiminde Veri Döndürme

Az önce söylediğimiz gibi, ön/arka uç ayrımı geliştirme modelinde arka uç, ön uca veri arayüzü sağlamalıdır; bu arayüzler genellikle JSON biçiminde veri döndürür. Django projesinde önce nesneyi sözlüğe dönüştürüp, sonra Django'nun kapsüllediği `JsonResponse` ile tarayıcıya JSON biçiminde veri döndürebiliriz; somut yöntem aşağıdaki gibidir.

```Python
def show_subjects(request):
    queryset = Subject.objects.all()
    subjects = []
    for subject in queryset:
        subjects.append({
            'no': subject.no,
            'name': subject.name,
            'intro': subject.intro,
            'isHot': subject.is_hot
        })
    return JsonResponse(subjects, safe=False)
```

Yukarıdaki kodda, dersleri sorgulayıp elde ettiğimiz `QuerySet` nesnesini döngüyle gezip her dersin verisini bir sözlüğe dönüştürüyoruz, sözlüğü `subjects` adlı liste kabına kaydediyoruz ve son olarak `JsonResponse` ile listenin serileştirmesini tamamlayıp tarayıcıya JSON biçiminde veri döndürüyoruz. `JsonResponse` bir liste (sözlük değil) serileştirdiğinden, `subjects` serileştirmesini tamamlamak için `safe` parametresini `False` yapmak gerekir; aksi halde `TypeError` istisnası oluşur.

Fark etmişsinizdir ki bir nesneyi sözlüğe dönüştüren kodu kendiniz yazmak zahmetlidir; nesnenin özellikleri çoksa ve bazı özellikler karmaşık bir nesneyle ilişkiliyse durum daha da kötüleşir. Bunun için `bpmappers` adlı üçüncü taraf kütüphaneyi kullanıp nesneyi sözlüğe dönüştürme işlemini basitleştirebiliriz; bu üçüncü taraf kütüphane Django framework desteği de sunar.

Üçüncü taraf `bpmappers` kütüphanesini kurun.

```Shell
pip install bpmappers
```

Eşleyiciyi yazın (nesneden sözlüğe dönüşümü gerçekleştirir).

```Python
from bpmappers.djangomodel import ModelMapper

from poll2.models import Subject


class SubjectMapper(ModelMapper):
   
    class Meta:
        model = Subject
```

Görünüm fonksiyonunu değiştirin.

```Python
def show_subjects(request):
    queryset = Subject.objects.all()
    subjects = []
    for subject in queryset:
        subjects.append(SubjectMapper(subject).as_dict())
    return JsonResponse(subjects, safe=False)
```

URL eşlemesini yapılandırın.

```Python
urlpatterns = [
    
    path('api/subjects/', show_subjects),
    
]
```

Ardından bu arayüze erişince aşağıdaki gibi JSON biçiminde veri elde edilir.

```JSON
[
    {
        "no": 1,
        "name": "Python Full Stack + Yapay Zeka",
        "intro": "Python bir bilgisayar programlama dilidir. Nesne yönelimli, dinamik tipli bir dildir; başlangıçta otomasyon betikleri (shell) yazmak için tasarlandı; sürümler güncellendikçe ve yeni işlevler eklendikçe bağımsız, büyük projelerin geliştirilmesinde giderek daha çok kullanılmaya başlandı.",
        "is_hot": true
    },
    // Burada sonraki içerik atlanmıştır
]
```

JSON verisinde dersin kuruluş zamanının görünmesini istemiyorsak eşleyicide `create_date` özelliğini dışlayabiliriz; popüler ders olup olmadığına karşılık gelen anahtarın `isHot` olmasını istiyorsak (varsayılan adı `is_hot`) eşleyiciyi değiştirerek de yapabiliriz. Somut yöntem aşağıdadır:

```Python
from bpmappers import RawField
from bpmappers.djangomodel import ModelMapper

from poll2.models import Subject


class SubjectMapper(ModelMapper):
    isHot = RawField('is_hot')

    class Meta:
        model = Subject
        exclude = ('is_hot', )
```

Ders arayüzünün döndürdüğü JSON verisine tekrar bakalım.

```JSON
[
    {
        "no": 101,
        "name": "Python Full Stack + Yapay Zeka",
        "intro": "Python bir bilgisayar programlama dilidir. Nesne yönelimli, dinamik tipli bir dildir; başlangıçta otomasyon betikleri (shell) yazmak için tasarlandı; sürümler güncellendikçe ve yeni işlevler eklendikçe bağımsız, büyük projelerin geliştirilmesinde giderek daha çok kullanılmaya başlandı.",
        "isHot": true
    },
    // Burada sonraki içerik atlanmıştır
]
```

`bpmappers`'ın ayrıntılı kullanım kılavuzu için [resmî dokümanına](<https://bpmappers.readthedocs.io/en/stable/>) bakın; bu resmî doküman Japonca yazılmıştır; tarayıcının çeviri işleviyle bildiğiniz dile çevirebilirsiniz.

### Vue.js ile Sayfa Render Etme

Şimdi ön yüz framework'ü Vue.js ile sayfa render'ını gerçekleştirelim. Vue.js'i kapsamlı öğrenmek istiyorsanız [resmî eğitimini](<https://cn.vuejs.org/v2/guide/>) okumanızı veya [YouTube](<https://www.youtube.com/>)da Vue.js yeni başlayan eğitimini (Vue.js Crash Course) aramanızı öneririz.

subjects.html sayfasını yeniden yazıp Vue.js ile sayfayı render edelim.

```HTML
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Ders Bilgisi</title>
    <style>
		/* Burada basamaklı stil sayfası atlanmıştır */
    </style>
</head>
<body>
    <div id="container">
        <h1>Örnek Akademi Tüm Dersleri</h1>
        <hr>
        <div id="main">
            <dl v-for="subject in subjects">
                <dt>
                    <a :href="'/static/html/teachers.html?sno=' + subject.no">
                        {{ subject.name }}
                    </a>
                    <img v-if="subject.is_hot" src="/static/images/hot-icon-small.png">
                </dt>
                <dd>{{ subject.intro }}</dd>
            </dl>
        </div>
    </div>
    <script src="https://cdn.bootcdn.net/ajax/libs/vue/2.6.11/vue.min.js"></script>
    <script>
        let app = new Vue({
            el: '#main',
            data: {
                subjects: []
            },
            created() {
                fetch('/api/subjects/')
                    .then(resp => resp.json())
                    .then(json => {
                        this.subjects = json
                    })
            }
        })
    </script>
</body>
</html>
```

Ön/arka uç ayrımıyla geliştirme, ön yüz sayfalarını statik kaynak olarak dağıtmayı gerektirir; proje gerçekten yayına alındığında tüm Web uygulamasında dinamik-statik ayrımı yaparız; statik kaynaklar Nginx veya Apache sunucusuyla dağıtılır; dinamik içerik üreten Python programı uWSGI veya Gunicorn sunucusuna dağıtılır; dinamik içerik istekleri Nginx veya Apache tarafından uWSGI veya Gunicorn sunucusuna yönlendirilir.

Geliştirme aşamasında genellikle Django'nun yerleşik test sunucusunu kullanırız; ön/arka uç ayrımını denemek istiyorsanız, statik sayfaları önce oluşturduğunuz statik kaynak dizinine koyabilirsiniz; somut yöntem için [projenin tam koduna](https://gitee.com/jackfrued/django19062) bakabilirsiniz.
