## RESTful Mimari ve DRF'te İleri Seviye

> **Translated to Turkish by** himmetcanumutlu

Bir önceki bölümdeki yöntem dışında, DRF ile REST tarzı veri arayüzü oluşturmak CBV (sınıf tabanlı görünüm) ile de yapılabilir. CBV ile veri arayüzü oluşturmanın özelliği kodun sade olması ve geliştirme verimliliğinin yüksek olmasıdır; ancak FBV (fonksiyon tabanlı görünüm) kadar esnek değildir; çünkü FBV kullanıldığında veri arayüzüne karşılık gelen görünüm fonksiyonunun hangi kodu çalıştıracağı ve hangi veriyi döndüreceği yüksek derecede özelleştirilebilir. Aşağıda ders veri arayüzünü özelleştirme örneğiyle CBV ile veri arayüzü özelleştirmenin somut yöntemini anlatıyoruz.

### CBV Kullanımı

#### APIView Alt Sınıfından Kalıtım

Önceki projedeki `polls/views.py` dosyasını değiştirip `show_subjects` görünüm fonksiyonunu kaldırın ve `SubjectView` adlı bir sınıf ekleyin; bu sınıf `ListAPIView`'den kalıtım alır; `ListAPIView` GET isteği alabilir; veri listesini alıp JSON verisi döndüren `get` metodunu kapsüller. `ListAPIView`, `APIView`'in alt sınıfıdır; `APIView`'in birçok alt sınıfı vardır; örneğin `CreateAPIView` POST isteğini, `UpdateAPIView` PUT ve PATCH isteğini, `DestoryAPIView` DELETE isteğini destekler. `SubjectView`'in kodu aşağıdaki gibidir.

```Python
from rest_framework.generics import ListAPIView


class SubjectView(ListAPIView):
    # queryset ile ders verisinin nasıl alınacağını belirtir
    queryset = Subject.objects.all()
    # serializer_class ile ders verisinin nasıl serileştirileceğini belirtir
    serializer_class = SubjectSerializer
```

Az önce söylediğimiz gibi, `SubjectView`'in üst sınıfı `ListAPIView` ders listesini alan GET isteğini işleyen `get` metodunu zaten gerçeklediğinden, yalnızca ders verisinin nasıl alınacağını ve nasıl serileştirileceğini bildirmemiz gerekir; birincisi `queryset` özelliğiyle, ikincisi `serializer_class` özelliğiyle belirtilir. Yukarıdaki `SubjectView`'i kullanmak için `urls.py` dosyasını aşağıdaki gibi değiştirmek gerekir.

```Python
urlpatterns = [
    path('api/subjects/', SubjectView.as_view()),   
]
```

Açıkça yukarıdaki yöntem, daha önce anlattığımız FBV'den çok daha basittir.

#### ModelViewSet'ten Kalıtım

Derse karşılık gelen veri arayüzünün, ders kaynağını alma, ekleme, güncelleme ve silme işlemlerini desteklemek için GET, POST, PUT, PATCH, DELETE isteklerini desteklemesi gerekiyorsa, daha basit yol `ModelViewSet`'ten kalıtım alarak ders görünüm sınıfını yazmaktır. `polls/views.py` dosyasını tekrar değiştirip `SubjectView` sınıfını kaldırın ve `SubjectViewSet` adlı bir sınıf ekleyin; kod aşağıdaki gibidir.

```Python
from rest_framework.viewsets import ModelViewSet


class SubjectViewSet(ModelViewSet):
    queryset = Subject.objects.all()
    serializer_class = SubjectSerializer
```

`ModelViewSet` sınıfının kaynak koduna bakınca, bu sınıfın 6 üst sınıfı olduğu görülür; ilk 5 üst sınıf sırasıyla POST (ders ekleme), GET (belirtilen dersi alma), PUT/PATCH (dersi güncelleme), DELETE (dersi silme) ve GET (ders listesini alma) işlemlerini destekler; karşılık gelen metotlar `create`, `retrieve`, `update`, `destroy` ve `list`'tir. `ModelViewSet`'in üst sınıfları bu metotları zaten gerçeklediğinden, neredeyse hiç kod yazmadan ders verisinin tam arayüz setini geliştirmiş olduk; yapmamız gereken yalnızca verinin nasıl alınacağını (`queryset` özelliğiyle) ve nasıl serileştirileceğini (`serializer_class` özelliğiyle) belirtmektir; bu, yukarıda `APIView` alt sınıfından kalıtım almaktaki yaklaşımla aynıdır.

```Python
class ModelViewSet(mixins.CreateModelMixin,
                   mixins.RetrieveModelMixin,
                   mixins.UpdateModelMixin,
                   mixins.DestroyModelMixin,
                   mixins.ListModelMixin,
                   GenericViewSet):
    """
    Varsayılan `create()`, `retrieve()`, `update()`,
    `partial_update()`, `destroy()` ve `list()` eylemlerini sağlayan görünüm seti.
    """
    pass
```

Yukarıdaki `SubjectViewSet`'i kullanmak için `urls.py` dosyasında URL eşlemesi yapmak gerekir. `ModelViewSet` birden çok görünüm fonksiyonunun özeti olduğundan, daha önceki URL eşleme biçiminden farklıdır; önce bir yönlendirici oluşturup onunla `SubjectViewSet`'i kaydetmemiz, sonra kayıt başarılı olduktan sonra üretilen URL'leri `urlpatterns` listesine eklememiz gerekir; kod aşağıdaki gibidir.

```Python
from rest_framework.routers import DefaultRouter

router = DefaultRouter()
router.register('api/subjects', SubjectViewSet)
urlpatterns += router.urls
```

`ModelViewSet` sınıfı dışında DRF, `ReadOnlyModelViewSet` adlı bir sınıf da sunar; adından anlaşılacağı gibi salt okunur görünümlerin kümesidir; yani bu sınıftan kalıtım alarak özelleştirilen veri arayüzü yalnızca GET isteğini, yani tek kaynağı ve kaynak listesini alma isteğini destekler.

### Veri Sayfalama

GET isteğiyle kaynak listesini alırken, veri miktarı gerçekten çok küçük değilse genellikle tüm veriyi tek seferde yüklemeyiz. Çoğu kaynak listesi alma işlemi sayfalamalı gösterimi destekler; yani sayfa numarası (veya sayfa numarasına benzer bir tanımlayıcı) ve sayfa boyutu (tek seferde kaç veri yükleneceği) belirterek farklı veri alabiliriz. `QuerySet` nesnesinin dilimleme işlemiyle sayfalama yapılabileceği gibi, Django framework'ünün kapsüllediği `Paginator` ve `Page` nesneleriyle de sayfalama yapılabilir. DRF kullanırken, Django yapılandırma dosyasında `REST_FRAMEWORK`'ü değiştirip varsayılan sayfalama sınıfını ve sayfa boyutunu yapılandırarak sayfalama yapılabilir; aşağıdaki gibidir.

```Python
REST_FRAMEWORK = {
    'PAGE_SIZE': 10,
    'DEFAULT_PAGINATION_CLASS': 'rest_framework.pagination.PageNumberPagination'
}
```

Yukarıda yapılandırılan `PageNumberPagination` sayfalayıcısı dışında DRF, `LimitOffsetPagination` ve `CursorPagination` sayfalayıcılarını da sunar; `CursorPagination` özellikle dikkat çekicidir; sayfa numarasıyla sayfalamada sitenin veri hacminin açığa çıkmasını önler; merak edenler kendileri inceleyebilir. Yapılandırma dosyasındaki varsayılan sayfalama ayarını kullanmak istemiyorsanız, görünüm sınıfına `pagination_class` özelliği ekleyip sayfalayıcıyı yeniden belirtebilirsiniz; bu özellik genellikle özel sayfalayıcıya atanır; aşağıdaki gibidir.

```Python
from rest_framework.pagination import PageNumberPagination


class CustomizedPagination(PageNumberPagination):
    # Varsayılan sayfa boyutu
    page_size = 5
    # Sayfa boyutuna karşılık gelen sorgu parametresi
    page_size_query_param = 'size'
    # Sayfa boyutunun maksimum değeri
    max_page_size = 50
```

```Python
class SubjectView(ListAPIView):
    # Verinin nasıl alınacağını belirtir
    queryset = Subject.objects.all()
    # Verinin nasıl serileştirileceğini belirtir
    serializer_class = SubjectSerializer
    # Nasıl sayfalanacağını belirtir
    pagination_class = CustomizedPagination
```

Veriyi sayfalamak istemiyorsanız, `pagination_class` özelliğini `None` yapıp varsayılan sayfalayıcıyı iptal edebilirsiniz.

### Veri Filtreleme

CBV ile öğretmen bilgi veri arayüzünü özelleştirmek istiyorsanız, `ListAPIView`'den kalıtım alarak da yapılabilir. Ancak belirtilen derse göre ilgili öğretmen bilgisini alacağımızdan, tüm öğretmen verisini doğrudan almak yerine öğretmen verisini filtrelemek gerekir. İstekten ders numarasını alıp ders numarasına göre öğretmenleri filtrelemek istiyorsanız, `get_queryset` metodunu yeniden yazarak yapılabilir; kod aşağıdaki gibidir.

```Python
class TeacherView(ListAPIView):
    serializer_class = TeacherSerializer

    def get_queryset(self):
        queryset = Teacher.objects.defer('subject')
        try:
            sno = self.request.GET.get('sno', '')
            queryset = queryset.filter(subject__no=sno)
            return queryset
        except ValueError:
            raise Http404('Öğretmen bulunamadı.')
```

Yukarıdaki yöntem dışında, DRF ile birlikte veri filtrelemeyi desteklemek için üçüncü taraf `django-filter` kütüphanesi de kullanılabilir; `django-filter` kullanıldıktan sonra, görünüm sınıfına `filter-backends` özelliğini yapılandırıp `DjangoFilterBackend` kullanarak veri filtreleme desteklenebilir. Yukarıdaki yapılandırma tamamlandıktan sonra `filter_fields` veya `filterset_class` özelliğiyle verinin nasıl filtreleneceği belirtilebilir; merak edenler kendileri inceleyebilir.
