## Python'da Eş Zamanlı Programlama-3

> **Translated to Turkish by** himmetcanumutlu

Tarayıcı tipik bir I/O yoğun görevdir; I/O yoğun görevlerin özelliği, programın I/O işlemleri nedeniyle sık sık bloklanma durumuna girmesidir; örneğin daha önce `requests` ile sayfa kodu veya ikili içerik alırken, bir istek gönderdikten sonra programın site yanıt verene dek beklemesi gerekir; hedef site güçlü değilse veya ağ durumu iyi değilse yanıt bekleme süresi çok uzun olabilir; bu süreçte tüm program orada bloklanıp hiçbir şey yapmaz. Önceki derslerden, tarayıcıyı hızlandırmak için çoklu iş parçacığı kullanılabileceğini biliyoruz; çoklu iş parçacığının özü, bir iş parçacığı bloklandığında programda çalışmaya devam edebilen başka iş parçacıklarının olmasıdır; böylece tüm program bloklanma ve beklemede çok zaman harcamaz.

Aslında I/O yoğun görevlere çok uygun bir eş zamanlı programlama yöntemi daha vardır: asenkron programlama; ona asenkron I/O da diyebilirsiniz. Bu yöntem, eş zamanlılığı birden çok iş parçacığı veya işlem başlatarak değil, birden çok alt programın birbiriyle iş birliği yapmasıyla CPU kullanımını artırıp, I/O yoğun görevlerde CPU kullanımının düşük olması sorununu çözer; ben buna genellikle "iş birlikçi eş zamanlılık" derim. Burada işletim sisteminin çeşitli I/O modlarını tartışmayacağım; çünkü birçok okuyucu için bu fazla soyut; ama iki kavram grubu sunmamız gerekir: "bloklama" ve "bloklamama" ile "senkron" ve "asenkron".

### Temel Kavramlar

#### Bloklama

Bloklama durumu, programın ihtiyaç duyduğu hesaplama kaynağını alamadığında askıya alınmasıdır. Program bir işlemin tamamlanmasını beklerken başka işleri işlemeye devam edemiyorsa, programın o işlemde bloklandığı söylenir. Bloklama her an olabilir; en tipik olanları I/O kesintisi (ağ I/O, disk I/O, kullanıcı girdisi dahil), uyuma işlemi, bir iş parçacığının bitmesini beklemek, hatta CPU bağlam değiştirirken bile program gerçekten çalışamaz; buna bloklama denir.

#### Bloklamama

Program bir işlemi beklerken kendisi bloklanmıyorsa, başka işleri işlemeye devam edebiliyorsa, programın o işlemde bloklamadığı söylenir. Bloklamama her program düzeyinde, her durumda var olamaz. Yalnızca programın kapsülleme düzeyi bağımsız alt program birimlerini içerebiliyorsa bloklamama durumu olabilir. Açıkça bir işlemin bloklanması programın zaman kaybına ve düşük verimliliğe yol açar; bu yüzden onu bloklamamaya çevirmek isteriz.

#### Senkron

Farklı program birimleri bir görevi tamamlamak için çalışırken belirli bir iletişim biçimiyle uyumlu hareket ediyorsa, bu program birimlerinin senkron çalıştığı söylenir. Örneğin daha önce anlattığımız banka hesabına para yatırma işleminde, kodu "kilit"i iletişim sinyali olarak kullanıp birden çok para yatırma işlemini sıraya sokarak senkron çalıştırdık.

#### Asenkron

Farklı program birimleri çalışırken iletişim koordinasyonuna gerek duymadan da bir görevi tamamlayabiliyorsa bu biçime asenkron denir. Örneğin tarayıcıyla sayfa indirirken, zamanlayıcı program indirme programını çağırdıktan sonra başka görevleri çizelgeleyebilir; o indirme göreviyle iletişim kurup davranışı koordine etmesi gerekmez. Farklı web sayfalarının indirilmesi ve kaydedilmesi birbiriyle ilişkisizdir; birbirine bildirim yapması da gerekmez. Açıkça asenkron işlemlerin tamamlanma anı ve sırası belirlenemez.

Birçok kişi bu kavramları tam olarak kavrayamaz; kısaca özetleyelim: senkron ve asenkronun odak noktası **mesaj iletişim mekanizmasıdır**, sonuçta "düzenli" ve "düzensiz" farkı olarak görünür; bloklama ve bloklamamanın odak noktası **programın mesaj beklerkenki durumudur**, sonuçta programın beklerken başka bir şey yapıp yapamaması olarak görünür. Bu içerikleri derinlemesine anlamak istiyorsanız klasik eser [《UNIX Ağ Programlama》](https://item.jd.com/11880047.html)yi okumanızı öneririz; bu kitap harikadır.

### Üreteçler ve Eş Yordamlar

Daha önce asenkron programlamanın bir "iş birlikçi eş zamanlılık" olduğunu; yani birden çok alt programın iş birliğiyle CPU kullanımını artırıp programın bloklanma ve beklemede harcadığı zamanı azaltıp sonunda eş zamanlılık etkisine ulaştığını söylemiştik. Birbiriyle iş birliği yapan birden çok alt programa "eş yordam" (coroutine) diyebiliriz; asenkron programlamayı gerçekleştirmenin anahtarıdır. Eş yordamı tanıtmadan önce aşağıdaki kodla üretecin ne olduğuna bakalım.

```Python
def fib(max_count):
    a, b = 0, 1
    for _ in range(max_count):
        a, b = b, a + b
        yield a
```

Yukarıda Fibonacci dizisi üreten bir üreteç yazdık; yukarıdaki `fib` fonksiyonunu çağırmak, fonksiyonu çalıştırıp dönüş değeri almak değildir; çünkü `fib` fonksiyonunda `yield` adlı özel bir anahtar sözcük vardır. Bu anahtar sözcük `fib` fonksiyonunu normal fonksiyondan farklı kılar; fonksiyonu çağırınca bir üreteç nesnesi elde edilir; bunu aşağıdaki kodla doğrulayabiliriz.

```Python
gen_obj = fib(20)
print(gen_obj)
```

Çıktı:

```
<generator object fib at 0x106daee40>
```

Yerleşik `next` fonksiyonuyla üreteç nesnesinden Fibonacci dizisinin değerini alabilir; `for-in` döngüsüyle de üretecin sağlayabildiği değerler üzerinde gezinebiliriz; kod aşağıdaki gibidir.

```Python
for value in gen_obj:
    print(value)
```

Üreteç ön aktivasyon yapıldıktan sonra bir eş yordamdır; diğer alt programlarla iş birliği yapabilir.

```Python
def calc_average():
    total, counter = 0, 0
    avg_value = None
    while True:
        curr_value = yield avg_value
        total += curr_value
        counter += 1
        avg_value = total / counter


def main():
    obj = calc_average()
    # Üreteci ön aktive et
    obj.send(None)
    for _ in range(5):
        print(obj.send(float(input())))


if __name__ == '__main__':
    main()
```

Yukarıdaki `main` fonksiyonu önce üreteç nesnesinin `send` metoduyla bir `None` değeri gönderip onu eş yordam olarak aktive eder; `next(obj)` ile de aynı etki elde edilir. Ardından eş yordam nesnesi `main` fonksiyonunun gönderdiği veriyi alıp verinin ortalamasını üretir (`yield`). Yukarıdaki örnekten iki alt programın nasıl "iş birliği" yaptığını fark ettiniz mi?

### Asenkron Fonksiyon

Python 3.5 sürümünde çok ilginç iki öğe eklendi: biri `async`, diğeri `await`; bunlar Python 3.7'de resmen anahtar sözcük oldu. Bu iki anahtar sözcükle eş yordam kodu yazmak basitleştirilebilir; birden çok alt programın iş birliği daha basit biçimde sağlanabilir. Bir örnekle açıklayalım; önce aşağıdaki koda bakın.

```Python
import time


def display(num):
    time.sleep(1)
    print(num)


def main():
    start = time.time()
    for i in range(1, 10):
        display(i)
    end = time.time()
    print(f'{end - start:.3f} saniye')


if __name__ == '__main__':
    main()
```

Yukarıdaki kod her çalıştırmada `1`'den `9`'a sayıları sırayla, her biri `1` saniye arayla çıktılar; tüm kodun çalışması yaklaşık `9` saniyeden fazla sürer; bunu herkesin anlayacağına inanıyorum. Fark ettiniz mi bilmem, bu kod senkron ve bloklamalı biçimde çalışır; senkronluk kodun çıktısından görülür; bloklama ise `display` fonksiyonu uyurken kodun diğer kısımlarının çalışamayıp uykunun bitmesini beklemek zorunda kalmasıdır.

Şimdi yukarıdaki kodu asenkron biçimde yeniden yazıp `display` fonksiyonunun asenkron çalışmasını sağlayalım.

```Python
import asyncio
import time


async def display(num):
    await asyncio.sleep(1)
    print(num)


def main():
    start = time.time()
    objs = [display(i) for i in range(1, 10)]
    loop = asyncio.get_event_loop()
    loop.run_until_complete(asyncio.wait(objs))
    loop.close()
    end = time.time()
    print(f'{end - start:.3f} saniye')


if __name__ == '__main__':
    main()
```

Python'daki `asyncio` modülü asenkron I/O desteği sunar. Yukarıdaki kodda önce `display` fonksiyonunun önüne `async` anahtar sözcüğünü ekleyip onu asenkron fonksiyon yaptık; asenkron fonksiyonu çağırmak fonksiyon gövdesini çalıştırmaz, bir eş yordam nesnesi elde eder. `display` fonksiyonundaki `time.sleep(1)`'i `await asyncio.sleep(1)` olarak değiştirdik; ikisinin farkı, ikincisinin tüm kodu bloklamamasıdır; çünkü `await` işlemi, diğer iş birlikçi alt programların CPU kaynağı alıp çalışma şansı bulmasını sağlar. Bu alt programların iş birliği yapabilmesi için onları bir olay döngüsüne (mesaj dağıtımı ve iletimi gerçekleştiren sistem) koymamız gerekir; çünkü **eş yordam I/O işlemiyle bloklandığında, olay döngüsüne I/O işleminin tamamlanıp tamamlanmadığını dinler ve kendi bağlamını ve uyanma fonksiyonunu kaydeder (çalışmayı sürdürmek için); sonra o eş yordam bloklanma durumuna geçer**. Yukarıdaki kodun 12. satırı `9` eş yordam nesnesi oluşturup bir listeye koyar; 13. satır `asyncio` modülünün `get_event_loop` fonksiyonuyla sistemin olay döngüsünü alır; 14. satır `asyncio` modülünün `run_until_complete` fonksiyonuyla eş yordam nesnelerini olay döngüsüne bağlar. Yukarıdaki kodu çalıştırınca, `9` eş yordamın (her biri `1` saniye bloklanır) toplamda yalnızca yaklaşık `1` saniye bloklandığı görülür; çünkü **bloklanan eş yordam nesnesi CPU'yu boşta bırakmak yerine CPU üzerindeki hakkından vazgeçer; bu yöntem CPU kullanımını büyük ölçüde artırır**. Ayrıca sayıların `1`'den `9`'a sırayla değil, farklı sırada çıktılandığını fark ederiz; istediğimiz sonuç budur; onların **asenkron çalıştığını** gösterir. Tarayıcı gibi I/O yoğun görevler için bu iş birlikçi eş zamanlılık, birçok senaryoda çoklu iş parçacığından daha iyi bir seçimdir; çünkü bu yaklaşım birden çok iş parçacığını yönetme, bakım yapma ve iş parçacığı geçişinin getirdiği maliyeti azaltır.

### aiohttp Kütüphanesi

Daha önce kullandığımız `requests` üçüncü taraf kütüphanesi asenkron I/O'yu desteklemez; tarayıcı kodunun çalışmasını hızlandırmak için asenkron I/O kullanmak istiyorsanız, `aiohttp` adlı üçüncü taraf kütüphaneyi kurup kullanabilirsiniz.

`aiohttp` kurulumu.

```Bash
pip install aiohttp
```

Aşağıdaki kod `aiohttp` ile `10` sitenin ana sayfasını çekip başlıklarını ayrıştırır.

```Python
import asyncio
import re

import aiohttp
from aiohttp import ClientSession

TITLE_PATTERN = re.compile(r'<title.*?>(.*?)</title>', re.DOTALL)


async def fetch_page_title(url):
    async with aiohttp.ClientSession(headers={
        'User-Agent': 'Mozilla/5.0 (Macintosh; Intel Mac OS X 10_14_6) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/95.0.4638.69 Safari/537.36',
    }) as session:  # type: ClientSession
        async with session.get(url, ssl=False) as resp:
            if resp.status == 200:
                html_code = await resp.text()
                matcher = TITLE_PATTERN.search(html_code)
                title = matcher.group(1).strip()
                print(title)


def main():
    urls = [
        'https://www.python.org/',
        'https://www.jd.com/',
        'https://www.baidu.com/',
        'https://www.taobao.com/',
        'https://git-scm.com/',
        'https://www.sohu.com/',
        'https://gitee.com/',
        'https://www.amazon.com/',
        'https://www.usa.gov/',
        'https://www.nasa.gov/'
    ]
    objs = [fetch_page_title(url) for url in urls]
    loop = asyncio.get_event_loop()
    loop.run_until_complete(asyncio.wait(objs))
    loop.close()


if __name__ == '__main__':
    main()
```
