### Süreç Oluşturma

Python'da `Process` sınıfına dayanarak süreç oluşturulabilir; süreç ve iş parçacığı arasında özsel fark olsa da `Process` sınıfı ile `Thread` sınıfının kullanımı çok benzerdir. `Process` sınıfının kurucusuyla nesne oluştururken de `target` parametresiyle sürecin çalıştıracağı kodu belirten bir fonksiyon geçilir; `args` ve `kwargs` parametreleriyle o fonksiyonun parametre değerleri belirtilir.

```Python
from multiprocessing import Process, current_process
from time import sleep


def sub_task(content, nums):
    # current_process fonksiyonuyla mevcut süreç nesnesini alır
    # süreç nesnesinin pid ve name özellikleriyle sürecin ID'si ve adı alınır
    print(f'PID: {current_process().pid}')
    print(f'Name: {current_process().name}')
    # Aşağıdaki çıktıdan görülebileceği gibi, her sürecin kendi nums listesi vardır, süreçler arasında bellek paylaşılmaz
    # Alt süreç oluşturulurken üst sürecin veri yapısı kopyalanır, üç süreç listeden pop(0) ile 20 değerini alır
    counter, total = 0, nums.pop(0)
    print(f'Loop count: {total}')
    sleep(0.5)
    while counter < total:
        counter += 1
        print(f'{counter}: {content}')
        sleep(0.01)


def main():
    nums = [20, 30, 40]
    # Belirtilen fonksiyonu çalıştırmak için süreç oluşturup başlat
    Process(target=sub_task, args=('Ping', nums)).start()
    Process(target=sub_task, args=('Pong', nums)).start()
    # sub_task fonksiyonunu ana süreçte çalıştır
    sub_task('Good', nums)


if __name__ == '__main__':
    main()
```

> **Not**: Yukarıdaki kod `current_process` fonksiyonuyla mevcut süreç nesnesini alır; süreç nesnesinin `pid` özelliğiyle süreç ID'sini alır. Python'da `os` modülünün `getpid` fonksiyonuyla da aynı etki elde edilir.

İsterseniz `os` modülünün `fork` fonksiyonuyla da süreç oluşturabilirsiniz; bu fonksiyon çağrıldığında işletim sistemi mevcut süreci (üst süreç) otomatik olarak kopyalar (alt süreç); üst sürecin `fork` fonksiyonu alt sürecin ID'sini döndürür; alt süreçteki `fork` fonksiyonu ise `0` döndürür; yani bu fonksiyon bir kez çağrıldığında üst ve alt süreçte iki farklı dönüş değeri alınır. Dikkat: Windows sistemi `fork` fonksiyonunu desteklemez; Linux veya macOS kullanıyorsanız aşağıdaki kodu deneyebilirsiniz.

```Python
import os

print(f'PID: {os.getpid()}')
pid = os.fork()
if pid == 0:
    print(f'Alt süreç - PID: {os.getpid()}')
    print('Yapılacak: alt süreçte çalıştırılacak kod')
else:
    print(f'Üst süreç - PID: {os.getpid()}')
    print('Yapılacak: üst süreçte çalıştırılacak kod')
```

Kısacası, çoklu işlemi oluşturup kullanmanın üç yolunu öneririz: doğrudan `Process` sınıfını kullanmak, `Process` sınıfından kalıtım almak ve süreç havuzu (`ProcessPoolExecutor`) kullanmak; bu üç yol yukarıdaki `fork` fonksiyonundan farklı olarak kodun uyumluluğunu ve taşınabilirliğini garanti eder. Somut yöntem daha önce çoklu iş parçacığı oluşturup kullanmaya yakındır; burada tekrar anlatmayacağız.

### Çoklu İşlem ve Çoklu İş Parçacığının Karşılaştırması

Tarayıcı gibi I/O yoğun görevler için çoklu işlemin pek avantajı yoktur; ama hesaplama yoğun görevler için çoklu işlem, çoklu iş parçacığına göre verimlilikte belirgin artış sağlar; bunu aşağıdaki kodla kanıtlayabiliriz. Aşağıdaki kod, çoklu iş parçacığı ve çoklu işlem olmak üzere iki yöntemle bir grup büyük tam sayının asal olup olmadığını belirler; açıkça bu hesaplama yoğun bir görevdir; görevleri sırasıyla birden çok iş parçacığına ve işleme koyup kodun çalışmasını hızlandırırız; çoklu iş parçacığı ve çoklu işlem kodunun somut performans farkına bakalım.

Önce çoklu iş parçacığı sürümünü gerçekleyelim; kod aşağıdaki gibidir.

```Python
import concurrent.futures

PRIMES = [
    1116281,
    1297337,
    104395303,
    472882027,
    533000389,
    817504243,
    982451653,
    112272535095293,
    112582705942171,
    112272535095293,
    115280095190773,
    115797848077099,
    1099726899285419
] * 5


def is_prime(n):
    """Asal sayı belirler"""
    for i in range(2, int(n ** 0.5) + 1):
        if n % i == 0:
            return False
    return n != 1


def main():
    """Ana fonksiyon"""
    with concurrent.futures.ThreadPoolExecutor(max_workers=16) as executor:
        for number, prime in zip(PRIMES, executor.map(is_prime, PRIMES)):
            print('%d asal mı: %s' % (number, prime))


if __name__ == '__main__':
    main()
```

Yukarıdaki kodun `example.py` adlı dosyaya kaydedildiğini varsayalım; Linux veya macOS'ta `time python example.py` komutuyla programı çalıştırıp işletim sisteminin çalışma süresi istatistiğini alabilirsiniz; macOS'umda bir çalıştırmanın son satırı şöyledir.

```
python example09.py  38.69s user 1.01s system 101% cpu 39.213 total
```

Sonuçtan görülebileceği gibi, çoklu iş parçacığı kodu CPU kullanımını ancak %100'e çıkarır; bu da çoklu iş parçacığı kodunun CPU çok çekirdek özelliğinden yararlanıp kodu hızlandıramadığını kanıtlar; şimdi çoklu işlem sürümüne bakalım; yukarıdaki koddaki iş parçacığı havuzunu (`ThreadPoolExecutor`) süreç havuzuyla (`ProcessPoolExecutor`) değiştirelim.

### Süreçler Arası İletişim

Süreçler arası iletişimi anlatmadan önce bir görev verelim: iki süreç başlatın; biri "Ping", diğeri "Pong" çıktısı versin; iki sürecin çıktıladığı "Ping" ve "Pong" toplamı 50'ye ulaştığında program bitsin. Kulağa çok basit geliyor; ama kod yazarken, birden çok süreç birden çok iş parçacığı gibi doğrudan paylaşılan bellek yoluyla veri alışverişi yapamadığından, aşağıdaki kod istediğimiz sonucu vermez.

```Python
from multiprocessing import Process
from time import sleep

counter = 0


def sub_task(string):
    global counter
    while counter < 50:
        print(string, end='', flush=True)
        counter += 1
        sleep(0.01)

        
def main():
    Process(target=sub_task, args=('Ping', )).start()
    Process(target=sub_task, args=('Pong', )).start()


if __name__ == '__main__':
    main()
```

Yukarıdaki kod sorunsuz görünüyor; ama sonuç "Ping" ve "Pong"un her birinden 50'şer adet çıktıdır. Tekrar hatırlatalım: programda süreç oluşturduğumuzda alt süreç üst süreci ve tüm veri yapılarını kopyalar; her alt sürecin kendi bağımsız bellek alanı vardır; bu da iki alt süreçte birer `counter` değişkeni olduğu ve ikisinin de `0`'dan `50`'ye çıkacağı anlamına gelir; sonuç tahmin edilebilirdir. Bu sorunu çözmenin nispeten basit yolu `multiprocessing` modülündeki `Queue` sınıfını kullanmaktır; bu, birden çok sürecin paylaşabildiği kuyruktur; alt seviyede işletim sisteminin boru ve semafor mekanizmasıyla gerçeklenir; kod aşağıdaki gibidir.

```Python
import time
from multiprocessing import Process, Queue


def sub_task(content, queue):
    counter = queue.get()
    while counter < 50:
        print(content, end='', flush=True)
        counter += 1
        queue.put(counter)
        time.sleep(0.01)
        counter = queue.get()


def main():
    queue = Queue()
    queue.put(0)
    p1 = Process(target=sub_task, args=('Ping', queue))
    p1.start()
    p2 = Process(target=sub_task, args=('Pong', queue))
    p2.start()
    while p1.is_alive() and p2.is_alive():
        pass
    queue.put(50)


if __name__ == '__main__':
    main()
```

> **İpucu**: `multiprocessing.Queue` nesnesinin `get` metodu varsayılan olarak kuyruk boşken bloklanır; veri alana dek dönmez. Metodun bloklanmamasını veya bloklanma süre sınırı belirlemeyi istiyorsanız `block` ve `timeout` parametrelerini belirtebilirsiniz.

Yukarıdaki kod, `Queue` sınıfının `get` ve `put` metotlarıyla üç sürecin (`p1`, `p2` ve ana süreç) veri paylaşmasını sağlar; buna süreçler arası iletişim denir; bu yöntemle `Queue`'dan alınan değer `50`'ye eşit veya büyük olduğunda `p1` ve `p2` `while` döngüsünden çıkıp sürecin çalışmasını sonlandırır. Kodun 22. satırındaki döngü, `p1` ve `p2` süreçlerinden birinin bitmesini beklemek içindir; bu sırada ana süreç `Queue`'ya `50`'ye eşit veya büyük bir değer koyar; böylece henüz bitmemiş diğer süreç de bu değeri okuyup sonlanır.

Süreçler arası iletişimin daha birçok yolu vardır; örneğin soketle de iki süreç iletişim kurabilir, hatta bu iki süreç aynı ana makinede olmayabilir; merak edenler kendileri inceleyebilir.

###  Özet

Python'da `subprocess` modülünün `call` fonksiyonuyla başka komutlar çalıştırıp alt süreç oluşturulabilir; bu, programımızda başka programları çağırmak gibidir; bu bilgiyi şimdilik tartışmayacağız; merak edenler kendileri inceleyebilir.

Python geliştiricileri için aşağıdaki durumlarda çoklu iş parçacığı kullanmayı düşünmek gerekir:

1. Program çok sayıda paylaşılan durumu (özellikle değiştirilebilir durumu) koruyorsa; Python'daki liste, sözlük ve küme iş parçacığı güvenlidir (birden çok iş parçacığı aynı liste, sözlük veya kümeyi aynı anda işlerken hata ve veri sorunu çıkmaz); bu yüzden paylaşılan durumu korumak için süreç yerine iş parçacığı kullanmanın maliyeti nispeten düşüktür.
2. Program zamanının büyük bölümünü I/O işlemlerinde harcıyorsa; çok fazla paralel hesaplama ihtiyacı yoksa ve çok fazla bellek kaplamıyorsa.

Şu durumlarda çoklu işlem kullanmayı düşünmek gerekir:

1. Program hesaplama yoğun görevler yürütüyorsa (ses/video kodlama-çözme, veri sıkıştırma, bilimsel hesaplama gibi).
2. Programın girdisi paralel olarak bloklara bölünebiliyorsa ve sonuçlar birleştirilebiliyorsa.
3. Programın bellek kullanımı kısıtlı değilse ve I/O işlemlerine (dosya okuma/yazma, soket gibi) güçlü bağımlılığı yoksa.
