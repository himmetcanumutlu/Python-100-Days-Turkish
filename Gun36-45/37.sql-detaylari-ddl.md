## SQL Detayları: DDL

> **Translated to Turkish by** himmetcanumutlu

SQL'i genellikle dört kategoriye ayırabiliriz: DDL (Veri Tanımlama Dili), DML (Veri İşleme Dili), DCL (Veri Kontrol Dili) ve TCL (İşlem Kontrol Dili). DDL esas olarak veritabanındaki nesneleri oluşturmak, silmek ve değiştirmek için kullanılır; örneğin iki boyutlu tabloları oluşturmak, silmek ve değiştirmek; çekirdek anahtar sözcükler `create`, `drop` ve `alter`'dir. DML esas olarak veri ekleme, silme, güncelleme ve sorgulamadan sorumludur; anahtar sözcükler `insert`, `delete`, `update` ve `select`'tir. DCL, yetki verme ve geri alma için kullanılır; çekirdek anahtar sözcükleri `grant` ve `revoke`'tur. TCL genellikle işlem kontrolü için kullanılır.

> **Not**: SQL, büyük/küçük harf duyarlı olmayan bir dildir; genellikle anahtar sözcükleri büyük, diğer kısımları küçük yazmanızı öneririz. Şirketin SQL programlama standardı zorunlu bir kural koyuyorsa şirketin isteğine uyun; kişisel tercih şirketin programlama standardının üzerine çıkmamalıdır; bu, profesyoneller için temel bilgidir.

### Veritabanı ve Tablo Oluşturma

Şimdi çok basit bir okul ders seçim sistemi veritabanı gerçekleyelim. Veritabanını `school` olarak adlandıracağız; dört anahtar varlık sırasıyla fakülte, öğretmen, öğrenci ve derstir. Öğrenci ile fakülte arasında aitlik ilişkisi vardır; bu ilişki sayı bakımından çoğa-bir ilişkisidir; çünkü bir fakültede birden çok öğrenci olabilirken bir öğrenci genellikle yalnızca bir fakülteye aittir. Aynı şekilde öğretmen ile fakülte arasındaki aitlik ilişkisi de çoğa-bir ilişkisidir. Bir öğretmen birden çok ders verebilir; bir dersin yalnızca bir öğretmeni varsa, ders ile öğretmen de çoğa-bir ilişkisidir; birden çok öğretmenin bir dersi birlikte vermesine izin veriliyorsa, ders ile öğretmen çoğa-çok ilişkisidir. Basitlik için ders ile öğretmeni çoğa-bir ilişki olarak tasarlıyoruz. Öğrenci ile ders tipik bir çoğa-çok ilişkisidir; çünkü bir öğrenci birden çok ders seçebilir, bir ders de birden çok öğrenci tarafından seçilebilir; ilişkisel veritabanı, iki varlığın çoğa-çok ilişkisini korumak için ara tablo kullanmak zorundadır. Sonuçta okul ders seçim sistemimizde beş tablo vardır: fakülte tablosu (`tb_college`), öğrenci tablosu (`tb_student`), öğretmen tablosu (`tb_teacher`), ders tablosu (`tb_course`) ve ders seçim kaydı tablosu (`tb_record`); ders seçim kaydı tablosu, öğrenci ile ders arasındaki çoğa-çok ilişkiyi koruyan ara tablodur.

```SQL
-- school adında bir veritabanı varsa sil
DROP DATABASE IF EXISTS `school`;

-- school adında veritabanı oluştur ve varsayılan karakter kümesi ile sıralama biçimini ayarla
CREATE DATABASE `school` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;

-- school veritabanı bağlamına geç
USE `school`;

-- Fakülte tablosu oluştur
CREATE TABLE `tb_college`
(
`col_id`    int unsigned AUTO_INCREMENT      COMMENT 'Numara',
`col_name`  varchar(50)  NOT NULL            COMMENT 'Ad',
`col_intro` varchar(500) NOT NULL DEFAULT '' COMMENT 'Tanıtım',
PRIMARY KEY (`col_id`)
);

-- Öğrenci tablosu oluştur
CREATE TABLE `tb_student`
(
`stu_id`    int unsigned NOT NULL           COMMENT 'Öğrenci no',
`stu_name`  varchar(20)  NOT NULL           COMMENT 'Ad',
`stu_sex`   boolean      NOT NULL DEFAULT 1 COMMENT 'Cinsiyet',
`stu_birth` date         NOT NULL           COMMENT 'Doğum tarihi',
`stu_addr`  varchar(255) DEFAULT ''         COMMENT 'Memleket',
`col_id`    int unsigned NOT NULL           COMMENT 'Bağlı fakülte',
PRIMARY KEY (`stu_id`),
CONSTRAINT `fk_student_col_id` FOREIGN KEY (`col_id`) REFERENCES `tb_college` (`col_id`)
);

-- Öğretmen tablosu oluştur
CREATE TABLE `tb_teacher`
(
`tea_id`    int unsigned NOT NULL                COMMENT 'Sicil no',
`tea_name`  varchar(20)  NOT NULL                COMMENT 'Ad',
`tea_title` varchar(10)  NOT NULL DEFAULT 'Asistan' COMMENT 'Unvan',
`col_id`    int unsigned NOT NULL                COMMENT 'Bağlı fakülte',
PRIMARY KEY (`tea_id`),
CONSTRAINT `fk_teacher_col_id` FOREIGN KEY (`col_id`) REFERENCES `tb_college` (`col_id`)
);

-- Ders tablosu oluştur
CREATE TABLE `tb_course`
(
`cou_id`     int unsigned NOT NULL COMMENT 'Numara',
`cou_name`   varchar(50)  NOT NULL COMMENT 'Ad',
`cou_credit` int          NOT NULL COMMENT 'Kredi',
`tea_id`     int unsigned NOT NULL COMMENT 'Ders veren öğretmen',
PRIMARY KEY (`cou_id`),
CONSTRAINT `fk_course_tea_id` FOREIGN KEY (`tea_id`) REFERENCES `tb_teacher` (`tea_id`)
);

-- Ders seçim kaydı tablosu oluştur
CREATE TABLE `tb_record`
(
`rec_id`   bigint unsigned AUTO_INCREMENT COMMENT 'Ders seçim kayıt no',
`stu_id`   int unsigned    NOT NULL       COMMENT 'Öğrenci no',
`cou_id`   int unsigned    NOT NULL       COMMENT 'Ders numarası',
`sel_date` date            NOT NULL       COMMENT 'Ders seçim tarihi',
`score`    decimal(4,1)                   COMMENT 'Sınav notu',
PRIMARY KEY (`rec_id`),
CONSTRAINT `fk_record_stu_id` FOREIGN KEY (`stu_id`) REFERENCES `tb_student` (`stu_id`),
CONSTRAINT `fk_record_cou_id` FOREIGN KEY (`cou_id`) REFERENCES `tb_course` (`cou_id`),
CONSTRAINT `uk_record_stu_cou` UNIQUE (`stu_id`, `cou_id`)
);
```

Yukarıdaki DDL'de vurgulanması gereken birkaç nokta var:

- Öncelikle, yukarıdaki SQL'de veritabanı adı, tablo adı ve alan adları ters tırnak (`) ile sarılmıştır; ters tırnak zorunlu değildir, ancak tablo adı, alan adı gibi adların SQL anahtar sözcükleriyle (SQL'de özel anlamı olan kelimeler) çakışması sorununu çözer.

- Veritabanı oluştururken `default character set utf8mb4` ile veritabanının varsayılan karakter kümesini `utf8mb4` (en fazla `4` baytlık `utf-8` kodlaması) olarak belirttik; bu karakter kümesini kullanmanızı öneririz; MySQL 8.x'in de varsayılan kullandığı karakter kümesidir; çünkü uluslararası kodlamayı destekler ve Emoji karakterlerini saklayabilir. - Veritabanı oluştururken ve silerken, `database` anahtar sözcüğü `schema` ile değiştirilebilir; ikisi aynı işlevi görür.

- Tablo oluşturma deyimindeki `not null` boş olmama kısıtıdır; alanın boş olamayacağını belirler; `default` alana varsayılan değer vermek içindir; buna varsayılan değer kısıtı deriz; `primary key` birincil anahtar kısıtıdır; bir kaydı benzersiz belirleyen sütunu belirler ve her kaydın eşsiz olmasını sağlar; çünkü birincil anahtar yinelenemez; `foreign key` yabancı anahtar kısıtıdır; iki tablonun referans bütünlüğünü korur. Örneğin öğrenci tablosunda col_id alanına yabancı anahtar kısıtı eklendiğinden, bu alan fakülte tablosundaki col_id'yi referans (`references`) almak zorundadır; bu yüzden öğrenci tablosundaki fakülte numarası, fakülte tablosundaki fakülte numarasından gelmelidir; bu alana gelişigüzel değer atanamaz. Birincil anahtar kısıtı, yabancı anahtar kısıtı gibi kısıtlara ad vermek gerekirse `constraint` anahtar sözcüğünü kullanıp arkasına kısıtın adını yazabilirsiniz.

- Tablo oluşturma deyimindeki `comment` anahtar sözcüğü, sütun ve tabloya yorum eklemek için kullanılır; kodun okunabilirliğini ve bakım kolaylığını artırır.

- Tablo oluştururken alt seviye depolama motoru seçilebilir. MySQL birçok depolama motorunu destekler; `show engines` komutuyla görüntülenebilir.   Veri tipi seçiminde, string verisi saklamak için genellikle VARCHAR ve CHAR olmak üzere iki tip kullanılır; birincisine genellikle değişken uzunluklu string, ikincisine ise sabit uzunluklu string denir. InnoDB depolama motoru için satır depolama biçimi sabit ve değişken uzunluklu sütunları ayırmaz; bu yüzden VARCHAR ile CHAR arasında esaslı bir fark yoktur; ikincisi mutlaka birincisinden daha performanslı değildir. Tarih-saat saklamak için DATETIME tipi TIMESTAMP'ten üstündür; çünkü birincisi daha geniş bir tarih-saat aralığını temsil edebilir; ikincisinin altında aslında bir tam sayı vardır ve belirtilen tarih-saatin 1970-01-01 00:00:00'den kaç milisaniye farklı olduğunu kaydeder; bu tip 2038-01-19 03:14:07'den sonra taşar.

MySQL 8.x'in başka birçok faydası da vardır; hem işlev hem performans açısından birçok optimizasyon ve ayar içerir; bu yüzden MySQL 8.x kullanmanızı kesinlikle öneririz. Yüksek eş zamanlı veritabanı erişim senaryolarında AUTO_INCREMENT hem performans sorunu yaratır hem de çoklu makine yapısında yinelenen ID değerleri üretebilir; bu senaryolarda dağıtık ID üretim algoritması (SnowFlake, TinyID vb.) kullanmak en iyi seçimdir; merak edenler kendileri inceleyebilir.

### Tablo Silme ve Değiştirme

Aşağıda öğrenci tablosu örneğiyle tablo silme ve değiştirme anlatılıyor. Tablo silmek için `drop table` kullanılabilir; kod aşağıdaki gibidir.

```SQL
DROP TABLE `tb_student`;
```

veya

```SQL
DROP TABLE IF EXISTS `tb_student`;
```

Dikkat edilmesi gereken nokta: öğrenci tablosuna veri girilmişse ve bu veri başka tablolar tarafından referans alınıyorsa, öğrenci tablosu silinemez; aksi halde yukarıdaki işlem hata verir. Bir sonraki derste tabloya veri eklemeyi anlatacağız; o zaman öğrenci tablosunu başarıyla silip silemeyeceğinizi deneyebilirsiniz.

Öğrenci tablosunu değiştirmek için `alter table` kullanılabilir; somut olarak birkaç duruma ayrılır:

Tabloyu değiştirip yeni bir sütun ekleme; örneğin öğrenci tablosuna iletişim telefonu sütunu ekleme.

```SQL
ALTER TABLE `tb_student` ADD COLUMN `stu_tel` varchar(20) NOT NULL COMMENT 'İletişim telefonu';
```

> **Dikkat**: Yeni sütun eklerken boş olmama kısıtı (`not null`) belirtilirse, öğrenci tablosunda veri olmamalıdır; aksi halde asıl veriler stu_tel sütunu eklendikten sonra boş kalır ve bu, boş olmama kısıtını ihlal eder. Elbette sütun eklerken varsayılan değer kısıtı kullanarak da bu sorunu çözebilirsiniz.

Tabloyu değiştirip belirtilen sütunu silme; örneğin yukarıda eklenen iletişim telefonu sütununu silme.

```SQL
ALTER TABLE `tb_student` DROP COLUMN `stu_tel`;
```

Tabloyu değiştirip sütunun veri tipini değiştirme; örneğin öğrenci tablosunun stu_sex sütununu karaktere çevirme.

```SQL
ALTER TABLE `tb_student` MODIFY COLUMN `stu_sex` char(1) NOT NULL DEFAULT 'M' COMMENT 'Cinsiyet';
```

Tabloyu değiştirip sütunun adını değiştirme; örneğin öğrenci tablosunun stu_sex sütununu stu_gender yapma.

```SQL
ALTER TABLE `tb_student` CHANGE COLUMN `stu_sex` `stu_gender` boolean DEFAULT 1 COMMENT 'Cinsiyet';
```

Tabloyu değiştirip kısıtı silme; örneğin öğrenci tablosunun col_id sütunundaki yabancı anahtar kısıtını silme.

```SQL
ALTER TABLE `tb_student` DROP FOREIGN KEY `fk_student_col_id`;
```

Tabloyu değiştirip kısıt ekleme; örneğin öğrenci tablosunun col_id sütununa yabancı anahtar kısıtı ekleme.

```SQL
ALTER TABLE `tb_student` ADD FOREIGN KEY (`col_id`) REFERENCES `tb_college` (`col_id`);
```

veya

```SQL
ALTER TABLE `tb_student` ADD CONSTRAINT `fk_student_col_id` FOREIGN KEY (`col_id`) REFERENCES `tb_college` (`col_id`);
```

> **Not**: Yabancı anahtar kısıtı eklerken, referans alınan tabloda silme ve güncelleme işlemi olduğunda nasıl davranılacağını `on update` ve `on delete` ile belirleyebilirsiniz; ikisinin de varsayılan değeri `restrict`'tir; yani yabancı anahtar kısıtı varsa, referans alınan verinin güncellenmesine ve silinmesine izin verilmez. `restrict` dışında olası değerler `cascade` (kademeli işlem) ve `set null` (boş yap)'dır; merak edenler kendileri inceleyebilir.

Tablonun adını değiştirme; örneğin öğrenci tablosunun adını tb_stu_info yapma.

```SQL
ALTER TABLE `tb_student` RENAME TO `tb_stu_info`;
```

> **İpucu**: Genellikle veritabanının veya tablonun adını gelişigüzel değiştirmeyin.
