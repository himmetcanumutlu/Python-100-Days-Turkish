### Hive'a Genel Bakış

[Hive](https://hive.apache.org/), Facebook'un açık kaynaklı, Hadoop tabanlı bir veri ambarı aracıdır; şu anda Apache Yazılım Vakfı tarafından bakımı yapılır; en yaygın kullanılan büyük veri çözümüdür. Basitçe söylemek gerekirse Hive, SQL sorgularını MapReduce veya Spark görevlerine dönüştürür; SQL'e mükemmel destek sunar; büyük veri istatistiğini çok kolay gerçekleştirir; Java ve Scala bilmeyenlerin de büyük veri platformunu ve dağıtık dosya sistemini kullanıp veriyi depolayıp işlemesini sağlar.

<img src="res/QQ20220708-235815@2x.png" style="zoom:50%;">

<img src="res/HADOOP-ECOSYSTEM-Edureka.png">

Hive'ın başlıca işlevleri:

1. Yapılandırılmış veri dosyasını bir tabloya eşler.
2. Büyük ölçekli veriyi işlemek için SQL benzeri HiveQL sorgu dili sunar.
3. Alt seviyede Hadoop'un HDFS depolamasına ve MapReduce / Spark / Tez motoruna dayanarak görev çalıştırır.

Hive'ın özellikleri şunlardır:

1. SQL benzeri sözdizimi: SQL sorgusunu destekler, büyük veri öğrenme eşiğini düşürür.
2. Ölçeklenebilirlik: PB düzeyinde veriyi nispeten kolay destekler.
3. Esnek depolama: birden çok depolama biçimini destekler (Text, ORC, Parquet, Avro vb.).
4. Seçilebilir hesaplama motoru: alt seviye yürütme motorları MapReduce, Tez, Spark'tır.
5. Gecikmesi yüksektir: çevrimdışı analize uygundur, düşük gecikmeli OLTP sorgularına uygun değildir.

### Temel Sözdizimi

1. Veritabanını silme.

    ```hive
    DROP DATABASE IF EXISTS eshop CASCADE;
    ```

2. Veritabanı oluşturma.

    ```hive

    ```

3. Bağlam değiştirme.

    ```hive
    USE eshop;
    ```

4. Dış tablo oluşturma.

    ```hive
    CREATE EXTERNAL TABLE IF NOT EXISTS dim_user_info 
    (
    user_id           STRING,
    user_name         STRING, 
    sex               STRING,
    age               INT,
    city              STRING,
    first_active_time STRING,
    level             INT,
    extra1            STRING,
    extra2            MAP<STRING, STRING>
    )
    ROW FORMAT DELIMITED 
    FIELDS TERMINATED BY '\t'
    COLLECTION ITEMS TERMINATED BY ','
    MAP KEYS TERMINATED BY ':'
    LINES TERMINATED BY '\n'
    STORED AS TEXTFILE;
    ```

6. Bölümlü tablo oluşturma.

   ```hive
   CREATE TABLE IF NOT EXISTS fact_user_trade 
   (
   user_name      STRING,
   piece          INT,
   price          DOUBLE,
   pay_amount     DOUBLE,
   goods_category STRING,
   pay_time       BIGINT
   )  
   PARTITIONED BY (dt STRING)

   FIELDS TERMINATED BY '\t'
   LINES TERMINATED BY '\n'

   ```

7. Dinamik bölüm ayarlama.

   ```hive
   -- Dinamik bölüm kullanımını ayarla
   SET hive.exec.dynamic.partition=true;
   -- Dinamik bölümü katı olmayan moda ayarla (katı modda en az bir dinamik bölüm sütunu belirtilmelidir)
   SET hive.exec.dynamic.partition.mode=nonstrict;
   -- Tek SQL işleminde en fazla kaç dinamik bölüm oluşturulabilir (düğümler arası)
   SET hive.exec.max.dynamic.partitions=1000;
   -- Her düğümde en fazla kaç dinamik bölüm oluşturulabilir
   SET hive.exec.max.dynamic.partitions.pernode=10000;
   ```

8. Bölüm onarma.

   ```hive
   MSCK REPAIR TABLE fact_user_trade;
   ```

9. Veri çıkarma.

   ```hive
   -- Yerel modu otomatik değerlendirmeyi aç
   SET hive.exec.mode.local.auto=true;
   -- MAPREDUCE dosya sayısını ayarla
   SET hive.exec.mode.local.auto.input.files.max=128;
   -- MAPREDUCE dosya boyutunu ayarla
   SET hive.exec.mode.local.auto.input.bytes.max=134217728;
   -- Reduce görev sayısını 1 yap
   SET mapreduce.job.reduces=1;
   
   -- Pekin'deki kadın kullanıcıların adından ilk 10'unu sorgula
   SELECT user_name 
     FROM dim_user_info
    WHERE city='beijing'
          AND sex='female'
    LIMIT 10;
   
   -- 24 Mart 2019'da food kategorisinden ürün satın alan kullanıcıların adını, adedini ve ödeme tutarını sorgula (toplamasız)
   SELECT user_name
        , piece
        , pay_amount
     FROM fact_user_trade
    WHERE dt='2019-03-24'
          AND goods_category='food';
   
   -- ELLA kullanıcısının 2018'deki toplam ödeme tutarını ve en yakın/en uzak iki tüketim aralığı gün sayısını say
   SELECT SUM(pay_amount) AS total
        , DATEDIFF(
              MAX(FROM_UNIXTIME(pay_time, 'yyyy-MM-dd')),
              MIN(FROM_UNIXTIME(pay_time, 'yyyy-MM-dd'))
          ) AS gap_days
     FROM fact_user_trade
    WHERE YEAR(dt)='2018'
          AND user_name='ELLA';
   ```

10. Gruplama ve toplama.

    ```hive
    -- 2019 Ocak-Nisan arasında her kategoriden kaç kişi satın aldı, toplam tutar ne kadar
    SELECT goods_category
         , COUNT(DISTINCT user_name) AS total_user
         , SUM(pay_amount) AS total_pay
      FROM fact_user_trade
     WHERE dt BETWEEN '2019-01-01' AND '2019-04-30'
     GROUP BY goods_category;
    
    -- Nisan 2019'da ödeme tutarı 50 bin TL'yi aşan kullanıcılar
    SELECT user_name
         , SUM(pay_amount) AS total
      FROM fact_user_trade
     WHERE dt BETWEEN '2019-04-01' AND '2019-04-30'
     GROUP BY user_name
    HAVING SUM(pay_amount) > 50000;
    
    -- 2018'de iki kategoriden fazla ürün satın alan kullanıcı sayısı
    SELECT COUNT(t.user_name)
      FROM (SELECT user_name
                 , COUNT(DISTINCT goods_category) AS total
              FROM fact_user_trade
             WHERE YEAR(dt)='2018'
             GROUP BY user_name
            HAVING COUNT(DISTINCT goods_category)>2) AS t;
            
    -- Nisan 2019'da ödeme tutarı en yüksek ilk 5 kullanıcı
    SELECT user_name
         , SUM(pay_amount) AS total
      FROM fact_user_trade
     WHERE dt BETWEEN '2019-04-01' AND '2019-04-30'
     GROUP BY user_name
     ORDER BY total DESC
     LIMIT 5;
            
    -- Farklı yaş gruplarındaki kullanıcı sayısını say
    SELECT CASE WHEN age < 20 THEN '20 altı' 
                WHEN age < 30 THEN '30 altı' 
                WHEN age < 40 THEN '40 altı' 
                ELSE '40 üstü' 
            END AS age_seg, 
           COUNT(DISTINCT user_id) AS total 
      FROM dim_user_info 
     GROUP BY CASE WHEN age < 20 THEN '20 altı' 
                   WHEN age < 30 THEN '30 altı' 
                   WHEN age < 40 THEN '40 altı' 
                   ELSE '40 üstü' 
               END;
    
    -- Aktivasyonu 2018'de olup 20-30 ve 30-40 yaş aralığındaki kullanıcıların medeni durumunu say
    SELECT age_seg,
           IF(marriage_status = 1, 'Evli', 'Bekar') AS marriage_status,
           COUNT(*) AS total
      FROM (SELECT CASE WHEN age < 20 THEN '20 altı' 
                        WHEN age < 30 THEN '20-30' 
                        WHEN age < 40 THEN '30-40' 
                        ELSE '40 üstü' 
                    END AS age_seg, 
                   extra2['marriage_status'] AS marriage_status
              FROM dim_user_info
             WHERE TO_DATE(first_active_time) BETWEEN '2018-01-01' AND '2018-12-31'
           ) AS t
     WHERE age_seg in ('20-30', '30-40')
     GROUP BY age_seg, IF(marriage_status = 1, 'Evli', 'Bekar');
    
    -- Her kullanıcının hangi kategorilerden ürün satın aldığını say
    SELECT user_name,
           COLLECT_SET(goods_category) AS categories
      FROM fact_user_trade
     GROUP BY user_name;
     
    -- Diziyi string'e birleştir
    SELECT user_name
         , CONCAT_WS(', ', COLLECT_SET(goods_category)) AS categories
      FROM fact_user_trade
     GROUP BY user_name;
    
    -- Veriyi eşleme (map) tipine dönüştür
    SELECT user_name
         , STR_TO_MAP(CONCAT_WS(',', COLLECT_LIST(CONCAT(goods_category, ':', cnt)))) AS category_cnt_map
      FROM (SELECT user_name
                 , goods_category
                 , COUNT(*) AS cnt
              FROM fact_user_trade
             GROUP BY user_name, goods_category) AS t
     GROUP BY user_name;
    ```

12. Yatay açılım.

     ```hive
     -- Görünüm oluştur
     CREATE OR REPLACE VIEW v_user_categories
     AS
     SELECT user_name
          , COLLECT_SET(goods_category) AS categories
       FROM fact_user_trade
      WHERE dt BETWEEN '2019-04-01' and '2019-04-30' 
      GROUP BY user_name;
     
     CREATE OR REPLACE VIEW v_user_categories_map
     AS
     SELECT user_name
          , STR_TO_MAP(CONCAT_WS(',', COLLECT_LIST(CONCAT(goods_category, ':', cnt)))) AS category_cnt_map
       FROM (SELECT user_name
                  , goods_category
                  , COUNT(*) AS cnt
               FROM fact_user_trade
              WHERE dt BETWEEN '2019-04-01' AND '2019-04-30' 
              GROUP BY user_name, goods_category) AS t
      GROUP BY user_name;
     
     -- Diziyi (array) yatay aç
      SELECT user_name
           , category
        FROM v_user_categories
     LATERAL VIEW EXPLODE(categories) t AS category;
     
     -- Eşlemeyi (map) yatay aç
      SELECT user_name
           , category
           , cnt
        FROM v_user_categories_map
     LATERAL VIEW EXPLODE(category_cnt_map) t AS category, cnt;
     ```

### Tablo Oluşturma İşlemleri

#### Veri Tipleri

Hive'ın veri tipleri kabaca üç sınıfa ayrılır: ilkel tip, karmaşık tip, iç içe tip.

| Veri tipi      | Tip açıklaması                                                 | Kullanım senaryosu |
| ------------- | -----------------------------------------------------| ------------- |
| TINYINT       | 1 bayt işaretli tam sayı, -128~127 aralığı.                |  |
| SMALLINT      | 2 bayt işaretli tam sayı, -32768 ~ 32767 aralığı.          |  |
| INT           | 4 bayt işaretli tam sayı, -2147483648~2147483647 aralığı. |  |
| BIGINT        | 8 bayt işaretli tam sayı, -9223372036854775808~9223372036854775807 aralığı. | Sayım, ID |
| BOOLEAN       | Mantıksal değer, TRUE veya FALSE.                               |  |
| FLOAT         | Tek duyarlıklı kayan noktalı sayı (4 bayt).                                 |  |
| DOUBLE        | Çift duyarlıklı kayan noktalı sayı (8 bayt).                                 |  |
| DECIMAL(P, S) | Yüksek hassasiyetli ondalık; P=toplam basamak, S=ondalık basamak.                        | Sipariş tutarı |
| STRING        | Uzunluğu değişken string | Metin, JSON |
| CHAR          | Sabit uzunluklu string |  |
| VARCHAR       | Maksimum uzunluğu sınırlı string |  |
| BINARY        | İkili veri |  |
| TIMESTAMP     | Zaman damgası | Milisaniye hassasiyetinde |
| DATE          | Tarih |  |
| INTERVAL      | Zaman aralığı tipi |  |
| STRUCT | C dilindeki yapıya benzer, `STRUCT<first_name:STRING, last_name:STRING>` | Oyuncu davranışı |
| MAP    | Anahtar-değer çiftlerinden oluşan elemanlar kümesi, `MAP<STRING, INT>`               | Ürün özniteliği |
| ARRAY    | Aynı tipte değişkenlerin kapsayıcısı, `ARRAY<STRING>`                   | Ekipman listesi |

Karmaşık ve iç içe tiplerin kullanımı aşağıdaki gibidir.

```hive
CREATE TABLE complex
(
  c1 ARRAY<INT>,
  c2 MAP<STRING, INT>,
  c3 STRUCT<a:STRING, b:INT, c:DOUBLE>,
  c4 STRUCT<name:STRING, addrs:ARRAY<STRUCT<city:STRING, zipcode:STRING>>>
);

SELECT c1[0]
     , c2['key']
     , c3.b
     , c4.addrs[0].city
  FROM complex;
```

Hive veri tipleri iki dönüşümü destekler:

1. Örtük dönüşüm: TINYINT → INT → BIGINT → DOUBLE → STRING, FLOAT → DOUBLE.

2. Açık dönüşüm:

   ```hive
   SELECT CAST('123' AS INT);
   SELECT CAST(3.14159 AS DECIMAL(5,2));
   ```

#### Tablo Tipleri

Hive'daki tablo tipleri şunlardır:

| Tablo tipi                         | Tanım/oluşturma biçimi                                                | Depolama konumu                                                | Yaşam döngüsü                                     | Özellik                                        | Uygulama senaryosu                          |
| ------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------- | -------------------------------------------- | ------------------------------------------- | --------------------------------- |
| **İç tablo (Managed Table)**     | `CREATE TABLE t1 (id INT, name STRING); `                    | Veri Hive ambar dizinindedir (`/user/hive/warehouse/...`) | **Tablo silinince veri de silinir**                     | Hive üst veriyi ve veriyi tamamen yönetir                   | Geçici veri, deneysel veri            |
| **Dış tablo (External Table)**    | `CREATE EXTERNAL TABLE t2 (id INT, name STRING) LOCATION '/data/t2'; ` | Veri kullanıcının belirttiği dizindedir                                  | **Tablo silinince veri korunur**, yalnızca üst veri silinir           | Üst veri ve veri ayrıdır, paylaşımı kolaydır                  | Veri paylaşımı, yanlış silmeyi önleme, veri gölü senaryosu    |
| **Bölümlü tablo (Partitioned Table)** | `CREATE TABLE sales (id INT, amount INT) PARTITIONED BY (dt STRING, region STRING); ` | Her bölüm bir alt dizine karşılık gelir                                  | Bölüm alanı tablo veri dosyasında değil, yol dizini olarak saklanır | Sorgu verimliliğini artırır (bölüme göre veri kırpma)              | Zaman serisi, bölge ayrımı, günlük verisi      |
| **Kovalı tablo (Bucketed Table)**    | `CREATE TABLE users (id INT, name STRING) CLUSTERED BY (id) INTO 8 BUCKETS; ` | Her kova bir dosyaya karşılık gelir                                    | Kova sayısı sabittir                                   | Veri kova dosyalarına karma ile dağıtılır, örnekleme ve Join optimizasyonuna uygundur | Eşitlikli Join, büyük tablo örnekleme, dengeli dağılım |
| **Geçici tablo (Temporary Table)**   | `CREATE TEMPORARY TABLE tmp (id INT); `                      | Yalnızca mevcut oturumun belleğindedir                                  | Oturum bitince otomatik yok olur                           | Diske yazılmaz, Hive üst verisini güncellemez                | Geçici hesaplama, oturum düzeyi ara sonuç          |
| **Görünüm (View)**                | `CREATE VIEW v1 AS SELECT ...; `                             | Veri saklamaz, yalnızca üst veri tanımı saklar                              | Alt tabloya bağlıdır                                 | Sanal tabloya benzer                                  | Veri güvenliği, SQL yeniden kullanımı, karmaşık sorguyu sarma  |

#### Niteleyiciler

Tablo oluştururken kullanılabilen niteleyiciler şunlardır:

| Anahtar sözcük                              | İşlev               | Yazıldığındaki etki                                                 | **Yazılmadığındaki varsayılan**                                           |
| ----------------------------------- | ------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **EXTERNAL**                        | Dış tablo belirtir         | `CREATE EXTERNAL TABLE ... LOCATION ...` → tablo ve veri ayrıdır, tablo silinince veri silinmez | **İç tablo (Managed Table)**, tablo silinince veri dizini de silinir         |
| **PARTITIONED BY**                  | Bölüm alanını tanımlar       | `PARTITIONED BY (dt STRING, city STRING)` → veri `/table/dt=2025-08-26/city=Beijing/` alt dizinine yazılır | **Bölümsüz tablo**, tüm veri tek dizindedir                         |
| **CLUSTERED BY ... INTO N BUCKETS** | Kovalamak               | `CLUSTERED BY (user_id) INTO 8 BUCKETS` → veri karmayla 8 dosya kovasına dağıtılır | **Kovasız**, veri normal dosyadır                                 |
| **STORED AS**                       | Dosya depolama biçimi       | Yaygın: `TEXTFILE`, `SEQUENCEFILE`, `ORC`, `PARQUET`           | **TEXTFILE**（metin dosyası）                                     |
| **ROW FORMAT**                      | Satır biçimini ve SerDe belirtir | Örneğin `ROW FORMAT DELIMITED FIELDS TERMINATED BY ','` veya `ROW FORMAT SERDE 'org.apache.hadoop.hive.serde2.JsonSerDe'` | **LazySimpleSerDe**（varsayılan ayraç `\001`, yani görünmez Ctrl+A） |
| **LOCATION**                        | HDFS yolunu belirtir     | `LOCATION '/user/hive/custom_path'` → tablo verisi özel yola saklanır | Varsayılan **ambar dizini**: `/user/hive/warehouse/<db>.db/<table>/` |
| **TBLPROPERTIES/DBPROPERTIES**      | Bazı üst veri özniteliklerini saklar | `TBLPROPERTIES ('creator'='Hao')`                            | **Boş**, elle eklenmedikçe                                         |
| **COMMENT**                         | Tablo/alan açıklaması        | `COMMENT 'Kullanıcı işlem olgu tablosu'`                                   | **Boş**                                                       |

### Veri Yazma

| Yazma biçimi                              | Örnek sözdizimi                                                     | Özellik                                                  | Uygun senaryo                                |

#### Uygulama Örnekleri

1. `FROM_UNIXTIME`: Zaman damgasını tarihe çevirir

   ```hive
   SELECT FROM_UNIXTIME(pay_time, 'yyyy-MM-dd hh:mm:ss')
     FROM fact_user_trade LIMIT 10;
   ```

3. `DATEDIFF`: İki tarih arasındaki farkı hesaplar

   ```Hive
   -- Kullanıcının ilk aktivasyon zamanı ile belirlenen referans zaman arasındaki fark
   SELECT user_name, DATEDIFF('2019-4-1', to_date(firstactivetime))
     FROM dim_user_info LIMIT 10;
   ```

4. `IF`: Koşula göre farklı değer döndürür

   ```Hive
   -- Farklı cinsiyetteki ileri seviye kullanıcı sayısı
   SELECT sex
        , IF(level > 5, 'Yüksek', 'Düşük') AS level_type
        , COUNT(DISTINCT user_id) AS total
     FROM dim_user_info
    GROUP BY sex, IF(level > 5, 'Yüksek', 'Düşük');
   ```
   
4. `SUBSTR`: String'den alt string alır

   ```Hive
   -- Her ay aktifleşen yeni kullanıcı sayısını say
   SELECT SUBSTR(first_active_time, 1, 7) AS month
        , COUNT(DISTINCT user_id) AS total
     FROM dim_user_info
    GROUP BY substr(first_active_time, 1, 7);
   ```

6. `GET_JSON_OBJECT`: JSON string'inden belirtilen `key`'e karşılık gelen `value`'yu alır; ör. `GET_JSON_OBJECT(info, '$.first_name')`.

   ```Hive
   -- Farklı telefon markasındaki kullanıcı sayısını say
   SELECT GET_JSON_OBJECT(extra1, '$.phonebrand') AS phone
        , COUNT(DISTINCT user_id) AS total
     FROM user_info
    GROUP BY GET_JSON_OBJECT(extra1, '$.phonebrand');
   ```
   
   > **Not**: MySQL'de buna karşılık gelen fonksiyonun adı `JSON_EXTRACT`'tir.

### Sıralama İşlemi

| Sıralama biçimi                    | Sözdizimi örneği                                                  | Çekirdek anlam                                        | Reducer sayısı             | Global sıralı mı                | Shuffle/sıralama davranışı                           | Performans ve dikkat noktaları                                             | Tipik kullanım                   |
| --------------------------- | --------------------------------------------------------- | ----------------------------------------------- | ---------------------- | --------------------------- | ------------------------------------------ | -------------------------------------------------------- | -------------------------- |
| **ORDER BY**                | `SELECT * FROM t ORDER BY ts DESC;`                       | **Global sıralama**                                    | **1 adet**（tek reducer） | Evet                          | Tüm veri 1 reducer'a girer, toplam sıralama yapılır           | En yavaş; tek nokta darboğazı; büyük sonuçta OOM kolay; küçük sonuç kümesi veya `LIMIT` ile uygun | Küçük sonuç dışa aktarma, nihai gösterim       |
| **ORDER BY … LIMIT**        | `SELECT * FROM t ORDER BY score DESC LIMIT 1000;`         | Global Top-N                                      | 1 adet                   | Evet                          | Yine tek reducer, ama `LIMIT` erken budama yapabilir        | Kabul edilebilir; Top-N'in yaygın yazımı                                   | Global Top-N                 |
| **SORT BY**                 | `SELECT * FROM t SORT BY ts DESC;`                        | **Her reducer içinde sıralama**（yerel sıralı）           | Birden çok                   | Hayır                          | Map çıktısı key'e göre çok reducer'a bölünür; her biri sıralar  | ORDER BY'den hızlı; sonuç bütünü **global sıralı değil**                    | Büyük tablo parça sıralama, paralel dışa aktarma     |
| **DISTRIBUTE BY**           | `SELECT * FROM t DISTRIBUTE BY key;`                      | **Key'e göre reducer'a dağıtımı** kontrol eder                   | Birden çok                   | Hayır                          | Aynı key aynı reducer'a gider; sıralama yok            | Sıklıkla SORT BY ile birlikte kullanılır                                    | Sonraki toplama/sıralama için bölümleme        |
| **DISTRIBUTE BY + SORT BY** | `SELECT * FROM t DISTRIBUTE BY key SORT BY key, ts DESC;` | **Aynı key aynı parça + parça içi sıralama**                  | Birden çok                   | Hayır（ama **her key içinde sıralı**） | Aynı key'in kayıtları aynı reducer içinde kurala göre sıralıdır | Yaygın; sonraki merge/sort tabanlı işleme yardımcı                     | Kullanıcı/ürün zaman serisi sıralama    |
| **CLUSTER BY**              | `SELECT * FROM t CLUSTER BY key;`                         | `DISTRIBUTE BY key` **+ `SORT BY key`（artan）** | Birden çok                   | Hayır                          | Sözdizimsel şeker, **ASC/DESC belirtilemez**              | Kısa; ama sıralama yönü kontrol edilemez                                   | Kova yazımı/eşitlikli Join ön sıralama  |
| **Bölüm içi sıralama**              | `... WHERE dt='2025-08-26' SORT BY ts;`                   | Yalnızca belirli bir bölümün verisini işler                            | Yapılandırmaya göre                 | Bölüm içi yerel sıralı              | SORT BY ile aynı                                 | Veri miktarını daraltıp belirgin hızlandırır                                       | Bölüm verisi dışa aktarma, pencere fonksiyonu ön hazırlık |

### Yatay Açılım

`LATERAL VIEW`, Hive'da çok önemli bir sözdizimidir; esas olarak tablo üreten fonksiyonlarla (`EXPLODE` gibi) birlikte, bir satır veriyi birden çok satıra böler. En yaygın uygulama senaryosu ARRAY, MAP, JSON gibi alanları işlemektir; geniş tablodan dar tabloya dönüşüm de yapılabilir.

| Kullanım                                 | Örnek sözdizimi                                                     | İşlev açıklaması                        | Tipik uygulama senaryosu           |
| ------------------------------------ | ------------------------------------------------------------ | ------------------------------- | ---------------------- |
| **LATERAL VIEW explode(array)**      | `SELECT order_id, item FROM orders LATERAL VIEW explode(items) t AS item; ` | Diziyi birden çok satıra böler, her eleman bir satır    | Sipariş detayı, olay gömme     |
| **LATERAL VIEW posexplode(array)**   | `SELECT order_id, pos, item FROM orders LATERAL VIEW explode(items) t AS pos, item; ` | Diziyi birden çok satıra böler, aynı anda eleman indisini çıkarır  | Sırayı koruyan tıklama akışı analizi   |
| **LATERAL VIEW explode(map)**        | `SELECT user_id, k, v FROM user_tags LATERAL VIEW explode(tags) t AS k, v; ` | Map'i birden çok satıra böler, (key, value) elde eder | Kullanıcı etiketi, öznitelik anahtar-değer çifti   |
| **LATERAL VIEW json_tuple(json, …)** | `SELECT log_id, ip, device FROM event_log LATERAL VIEW json_tuple(log_json,'ip','device') t AS ip, device; ` | JSON'dan alan çıkarıp sütun üretir      | Günlük ayrıştırma, yarı yapılandırılmış veri |
| **LATERAL VIEW inline(array)**       | `SELECT order_id, col1, col2 FROM orders LATERAL VIEW inline(item_structs) t AS col1,col2; ` | struct dizisini birden çok satır ve sütuna açar       | Tek satırda çok boyutlu öznitelik saklarken bölme   |
| **LATERAL VIEW stack(n, …)**         | `SELECT user_id, subject, score FROM user_score LATERAL VIEW stack(3,'math',math,'eng',english,'phy',physics) t AS subject, score; ` | Birden çok sütunu birden çok satıra çevirir (sütundan satıra)         | Geniş tabloyu uzun tabloya çevirme, UNPIVOT    |

### HiveSQL vs. MySQL

| **Özellik**              | **Hive SQL**                                                 | **MySQL SQL**                                                | **Fark Açıklaması**                                                 |
| --------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **Tablo bölümleme**            | `PARTITIONED BY`（bölüm）：Tablo oluştururken veriyi bir alana göre böler, sorguda veri filtrelemeyi hızlandırır. | Bölüm desteklemez.                                                 | Hive bölümle veriyi ayrı depolayabilir, büyük veri senaryosuna uygundur. MySQL'de benzer bölüm mekanizması yoktur. |
| **Tablo kovalama**            | `CLUSTERED BY`（kova）: Tablo verisini bir alana göre kovalar, büyük tablo birleştirme optimizasyonuna uygundur. | Kova desteklemez.                                                 | Hive kova ile birleştirmeyi optimize eder, MySQL kova işlevini desteklemez.          |
| **Depolama biçimi**          | `STORED AS`: ORC, Parquet gibi sütunlu depolama biçimlerini destekler.                | InnoDB gibi satırlı depolama kullanır.                                     | Hive sütunlu depolamayı destekler, sorgu ve sıkıştırmayı optimize eder; MySQL ağırlıklı satırlı kullanır. |
| **Sorgu motoru**          | MapReduce, Tez, Spark gibi birden çok yürütme motorunu destekler.                    | Yalnızca InnoDB motorunu destekler.                                           | Hive sorgusu farklı motorla (Tez, Spark) hızlandırılabilir, MySQL tek motor kullanır. |
| **Karmaşık sorgu desteği**      | LATERAL VIEW, MAP, ARRAY gibi karmaşık veri yapılarını destekler.             | LATERAL VIEW gibi karmaşık veri tipi ve işlemeyi desteklemez.                   | Hive daha karmaşık iç içe sorgu ve veri tipini destekler, MySQL benzer işlevi desteklemez. |
| **JOIN tipi**          | MapJoin (Map-side Join) destekler: küçük tabloyu belleğe yükleyip Map aşamasında birleştirir, Shuffle'dan kaçınır. | Standart INNER JOIN, LEFT JOIN, RIGHT JOIN, OUTER JOIN destekler.  | Hive MapJoin küçük-büyük tablo birleştirmeyi hızlandırır, MySQL'de MapJoin optimizasyonu yoktur. |
| **Özel fonksiyon (UDF)** | Kullanıcı tanımlı fonksiyon (UDF) ve kullanıcı tanımlı tablo fonksiyonu (UDTF) destekler.            | Kullanıcı tanımlı fonksiyon (UDF) ve tetikleyici destekler.                            | Hive özel fonksiyon esnekliğine odaklanır, MySQL tablo işlemiyle ilgili fonksiyonlara. |
| **Sorgu optimizasyonu**          | Bölüm kırpma, sütun kırpma, dinamik bölüm ekleme gibi optimizasyonları destekler. | İndekse dayalı optimizasyon, ama Hive gibi sütun/bölüm kırpmayı desteklemez.         | Hive büyük veriye yönelik daha çok optimizasyona sahiptir, MySQL indeks ve sorgu önbelleğine dayanır. |
| **İndeks**              | `CREATE INDEX` destekler: ama Hive'da indeks kullanımı genellikle önerilmez, performans maliyeti yüksektir. | `CREATE INDEX` destekler; indeks MySQL sorgu performansının anahtarlarından biridir.          | Hive'da indeks kullanımı görece az ve kaynak tüketicidir; MySQL indeksle sorguyu büyük ölçüde hızlandırır. |
| **Veri tipi**          | `ARRAY`, `MAP`, `STRUCT` gibi karmaşık veri tiplerini destekler.                 | Yalnızca `INT`, `VARCHAR` gibi temel tipleri destekler.                   | Hive daha zengin veri tipini destekler, özellikle yapılandırılmış veride; MySQL görece basittir. |
| **NULL işleme**        | `IS NULL`, `IS NOT NULL` destekler; ama bazen NULL işlemesi MySQL'den farklı olabilir, davranış yürütme motorundan etkilenebilir. | `IS NULL`, `IS NOT NULL` destekler; NULL işlemesi tutarlıdır.           | İkisi de NULL kontrolünü destekler, ama büyük veri sorgusunda Hive'ın NULL işlemesi MySQL kadar hassas olmayabilir. |
| **Toplama fonksiyonu**          | Yaygın toplama fonksiyonlarını (`SUM()`, `COUNT()`, `AVG()` vb.) destekler ve `APPROX_COUNT_DISTINCT()` gibi yaklaşık toplama fonksiyonlarını genişletir. | Yaygın toplama fonksiyonlarını (`SUM()`, `COUNT()`, `AVG()` vb.) destekler.      | Hive `APPROX_COUNT_DISTINCT()` gibi verimli yaklaşık fonksiyonlar sunar, devasa veriye uygundur; MySQL toplaması genellikle hassastır. |
| **Alt sorgu desteği**        | Alt sorguyu destekler, ama büyük veri kümesinde MySQL kadar verimli olmayabilir, genellikle `MAPJOIN` gibi optimizasyonla hızlandırılır. | Alt sorguyu destekler; MySQL alt sorgu optimizasyonu iyidir, özellikle küçük veride. | Hive alt sorgusu büyük veride MySQL'den yavaş olabilir; MySQL alt sorgu optimizasyonu daha olgundur. |
| **Tablo oluşturma sözdizimi**        | Hive'da tablo oluştururken depolama biçimi, bölüm, dosya biçimi belirtilir.   | MySQL'de tablo oluştururken ağırlıklı alan tipi ve indekse odaklanılır.          | Hive tablo oluşturması daha karmaşıktır, depolama biçimi ve bölüm içerir; büyük veriye uygundur; MySQL daha sadedir. |
| **Maddileştirilmiş görünüm**          | Hive **maddileştirilmiş görünüm** (Materialized View) oluşturmayı destekler; bazı durumlarda sorgu performansını artırır. | MySQL maddileştirilmiş görünümü doğrudan desteklemez; geçici tablo veya uygulama önbelleğiyle benzer işlev yapar. | Hive maddileştirilmiş görünüm sunar; önceden hesaplanmış sonucu saklar. MySQL'de yerleşik maddileştirilmiş görünüm yoktur. |
| **Sorgu önbelleği**          | Hive sorgu önbelleğini desteklemez; MapJoin, indeks gibi yollarla optimizasyon yapar. | MySQL sorgu önbelleğini destekler; yaygın sorgu sonuçlarını önbelleğe alıp verimliliği artırır.    | MySQL güçlü sorgu önbelleğine sahiptir; Hive başka optimizasyon stratejilerine dayanır. |
| **String fonksiyonları**        | Hive `CONCAT()`, `LENGTH()`, `SUBSTRING()` gibi string fonksiyonlarını destekler. | MySQL de string fonksiyonlarını destekler, destek düzeyi oldukça kapsamlıdır.              | İkisi benzer string işlemlerini destekler, ama Hive'ın string işlemesi büyük veri analizine daha uygundur. |
| **NULL varsayılan değer**        | Hive'da alan için NULL varsayılan değer genellikle desteklenmez; veri eklerken `INSERT INTO` kullanılır. | MySQL tablo oluştururken alan için NULL veya varsayılan değer belirlemeye izin verir.                  | Hive alan varsayılan değerini doğrudan desteklemez; MySQL (NULL dahil) varsayılan değere izin verir. |

### Performans Optimizasyonu

Hive SQL sorgu performansını optimize etmenin birçok yolu vardır; tablo yapısı tasarımından sorgu optimizasyonuna, yürütme motoru ayarına kadar farklı yönlerden farklı optimizasyon biçimleri vardır.

| **Optimizasyon yöntemi**                       | **Açıklama**                                                     | **Uygun senaryo**                                                 |
| ---------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **Bölümleme**（Partitioning）           | Tabloyu bir alana (tarih gibi) göre böler. Bölüm kırpmayla yalnızca koşula uyan bölümler taranır, taranan veri azalır. | Veri büyükse ve sorgu genellikle bir alana (zaman, bölge) göre filtreleniyorsa. |
| **Kovalama**（Bucketing）              | Veriyi bir alanın karma değerine göre sabit sayıda kovaya böler. Büyük-küçük tablo birleştirmede, özellikle toplamada optimize eder. | Verimli birleştirme ve toplama gerektiğinde, özellikle bir sütunda tekrar tekrar işlem yapılırken.   |
| **Sütun kırpma**（Column Pruning）       | Sorguda yalnızca gerekli sütunları seçer, gereksiz sütun taramasını azaltır.                   | Sorguda yalnızca tablonun bir kısım sütunu gerektiğinde.                                 |
| **Bölüm kırpma**（Partition Pruning）  | Koşula uymayan bölümleri kırpıp yalnızca koşulu sağlayan bölümleri tarar.     | Tablo bölümlüyse ve sorgu bölüm alanının filtre koşulunu içeriyorsa.                 |
| **Sıkıştırılmış depolama biçimi**（ORC, Parquet）   | Sütunlu depolama biçimi (ORC, Parquet) kullanır; satırlıdan (TextFile) daha verimlidir, özellikle büyük veri okurken. | Tablo verisi büyükse, özellikle hızlı tarama gerektiğinde.                       |
| **MapJoin**（Map-side Join）       | Küçük tablo ile büyük tabloyu birleştirirken küçük tabloyu belleğe yükleyip Map aşamasında birleştirir; Shuffle ve Reduce maliyetinden kaçınır. | Küçük tablo belleğe sığacak kadar küçükse, küçük-büyük tablo birleştirmede.     |
| **Uygun Join tipi**                 | Uygun Join tipi (Sort Merge Join veya Bucketed Join) birleştirme verimliliğini optimize eder. | İki tablo da aynı sütuna göre kovalanmış veya sıralanmışsa.                       |
| **Uygun Hive yürütme motoru**           | Uygun yürütme motoru (MapReduce, Tez, Spark) seçmek sorgu verimliliğini artırır. Tez veya Spark genellikle MapReduce'tan verimlidir. | Veri miktarı ve sorgu tipine göre farklı motor seçilir.                     |
| **Uygun dosya biçimi**             | Uygun dosya biçimi (ORC, Parquet) depolama ve okuma verimliliğini artırır, özellikle büyük ölçekli veride. | Verimli depolama ve okuma gerektiğinde.                                       |
| **Dinamik bölüm eklemeyi açma**               | `hive.exec.dynamic.partition=true` ayarlayarak dinamik bölüm ekleme yapılır, her bölümü elle belirtmekten kaçınılır. | Veri bölüme göre dinamik eklenirken, elle bölüm belirtmekten kaçınmak için.               |
| **Veri taramasını azaltma**（hesabı erteleme）       | `WHERE` alt cümlesiyle sorguda gereksiz veriyi taramaktan kaçınılır; veriyi mümkün olduğunca erken aşamada filtreler. | Sorgu büyük veri içeriyorsa, erken aşamada taranan veriyi azaltmaya çalışın. |
| **Parça parça çalıştırma**                     | Sorgu sonucunda `LIMIT` ile sayfalama veya `TABLESAMPLE` ile veri örnekleme yaparak veri miktarını azaltır. | Veri çok büyükse ve bütünlük şartı yüksek değilse.                   |
| **Uygun indeks kullanımı**                   | Sorguyu hızlandırmak için indeks oluşturur, özellikle sık sorgulanan koşul sütunlarında. | Bazı sütunlar sık sorgu koşulu olarak kullanılıyorsa.                                 |
| **Sorgu önbelleği**                       | Hive sorgu önbelleğini açıp sonuç kümesini önbelleğe alır, aynı sorgunun verimliliğini artırır. | Aynı sorgu sık çalıştırılıyorsa.                                     |
| **MapReduce görev sayısını azaltma**          | `mapreduce.map.memory.mb` ve `mapreduce.reduce.memory.mb` gibi parametreleri ayarlayarak MapReduce görev sayısını azaltır, verimliliği artırır. | Sorguda birden çok karmaşık MapReduce görevi varsa.                      |
| **Tablo depolama biçimini uygun seçme**           | Tabloya uygun depolama biçimi seçilir; biçim uyumsuzluğundan kaynaklı performans sorunu önlenir. ORC ve Parquet büyük veri sorgusunda daha verimlidir. | Sorgu verisi çok büyükse, özellikle okuma ve toplamada.                   |
| **Maddileştirilmiş görünüm**（Materialized View）  | Maddileştirilmiş görünüm oluşturup sonucu önceden hesaplayıp saklar; yinelenen hesaplama maliyetini azaltır.   | Bazı sorgu sonuçları sık kullanılıyorsa.     |
| **Paralel yürütme**（Parallel Execution） | Paralel yürütmeyi kullanır, `hive.exec.parallel=true` ayarlayıp birden çok sorguyu paralel çalıştırır, süreyi azaltır. | Birden çok sorgu çalıştırılıp paralelleştirilebiliyorsa.                             |
