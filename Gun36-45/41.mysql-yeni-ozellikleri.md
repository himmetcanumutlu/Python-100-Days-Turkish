## MySQL'in Yeni Özellikleri

### JSON Tipi

Birçok geliştirici, ilişkisel veritabanıyla veri kalıcılaştırma yaparken, yapılandırılmış depolamanın esneklikten yoksun olduğunu hisseder; çünkü tüm sütunları ve ilgili veri tiplerini önceden tasarlamak gerekir. İş geliştikçe ve değiştikçe, tablo yapısını değiştirmek gerekirse bu kesinlikle zahmetli ve can sıkıcıdır. MySQL 5.7 sürümünden itibaren MySQL, JSON veri tipi desteğini ekledi (MySQL 8.0, JSON'un günlük performans darboğazını çözdü); JSON tipini iyi kullanmak, aslında ilişkisel veritabanı ile ilişkisel olmayan veritabanı arasındaki sınırı kaldırıp veri kalıcılaştırma işlemlerine daha fazla kolaylık getirir.

JSON tipi esas olarak JSON nesnesi ve JSON dizisi olmak üzere ikiye ayrılır; aşağıdaki gibidir.

1. JSON nesnesi

```JSON
{"name": "骆昊", "tel": "13122335566", "QQ": "957658"}
```

2. JSON dizisi

```JSON
[1, 2, 3]
```

```JSON
[{"name": "骆昊", "tel": "13122335566"}, {"name": "Ahmet Yılmaz", "QQ": "123456"}]
```

JSON tipi nerelerde gerekir? Basit bir örnek verelim: günümüzde birçok ürünün kullanıcı girişi telefon, WeChat, QQ, Weibo gibi birden çok yolu destekler; ancak genellikle kullanıcıdan tüm bu bilgileri vermesini istemeyiz. O zaman geleneksel tasarımla, birden çok giriş yoluna karşılık birden çok sütun tasarlamak gerekir; ayrıca bu sütunların boş olmasına izin vermek de gerekebilir; bu açıkça iyi bir seçim değildir. Öte yandan ürün bir giriş yolu daha eklerse, önceki tablo yapısını değiştirmek zorunlu olur; bu da daha can sıkıcıdır. Ancak JSON tipiyle az önceki sorun çözülür; aşağıdaki gibi bir tasarım yapabiliriz.

```SQL
CREATE TABLE `tb_test`
(
`user_id`    bigint unsigned,
`login_info` json,
PRIMARY KEY (`user_id`)
);

INSERT INTO `tb_test` 
VALUES 
    (1, '{"tel": "13122335566", "QQ": "654321", "wechat": "jackfrued"}'),
    (2, '{"tel": "13599876543", "weibo": "wangdachui123"}');
```

Kullanıcının telefon ve WeChat numarasını sorgulamak için aşağıdaki SQL deyimi kullanılabilir.

```SQL
SELECT `user_id`
     , JSON_UNQUOTE(JSON_EXTRACT(`login_info`, '$.tel')) AS telefon
     , JSON_UNQUOTE(JSON_EXTRACT(`login_info`, '$.wechat')) AS wechat 
FROM `tb_test`;
```

```
+---------+-------------+-----------+
| user_id | telefon     | wechat     |
+---------+-------------+-----------+
|       1 | 13122335566 | jackfrued |
|       2 | 13599876543 | NULL      |
+---------+-------------+-----------+
```

JSON tipini desteklediği için MySQL, yukarıda kullanılan `json_extract` ve `json_unquote` gibi JSON verisi işleyen eşleşen fonksiyonlar da sunar. Elbette yukarıdaki SQL'in daha pratik bir yazımı da vardır; aşağıdaki gibidir.

```SQL
SELECT `user_id`
     , `login_info` ->> '$.tel' AS telefon
     , `login_info` ->> '$.wechat' AS wechat
  FROM `tb_test`;
```

Bir örnek daha: ürünümüz kullanıcı profili (user profiling; kullanıcıya etiket verme) işlevini gerçekleştirip, kullanıcı profiline dayanarak platformun hizmet veya tüketim ürünlerini önermek istiyorsa, kullanıcı profili verisini saklamak için de JSON tipini kullanabiliriz; örnek kod aşağıdaki gibidir.

Profil etiket tablosunu oluşturma.

```SQL
CREATE TABLE `tb_tags`
(
`tag_id`   int unsigned NOT NULL COMMENT 'Etiket ID',
`tag_name` varchar(20)  NOT NULL COMMENT 'Etiket adı',
PRIMARY KEY (`tag_id`)
);

INSERT INTO `tb_tags` (`tag_id`, `tag_name`) 
VALUES
    (1, '70\'ler'),
    (2, '80\'ler'),
    (3, '90\'lar'),
    (4, '00\'ler'),
    (5, 'Sporu sever'),
    (6, 'Yüksek eğitimli'),
    (7, 'Burjuva'),
    (8, 'Evi var'),
    (9, 'Arabası var'),
    (10, 'Film izlemeyi sever'),
    (11, 'Online alışverişi sever'),
    (12, 'Sık dışarıdan söyler');
```

Kullanıcıya etiket verme.

```SQL
CREATE TABLE `tb_users_tags`
(
`user_id`   bigint unsigned NOT NULL COMMENT 'Kullanıcı ID',
`user_tags` json            NOT NULL COMMENT 'Kullanıcı etiketleri'
);

INSERT INTO `tb_users_tags`
VALUES
    (1, '[2, 6, 8, 10]'),
    (2, '[3, 10, 12]'),
    (3, '[3, 8, 9, 11]');
```

Şimdi bir grup sorguyla JSON tipinin inceliklerini öğrenelim.

1. Film izlemeyi seven (`10` etiketine sahip) kullanıcıların ID'sini sorgula.

    ```SQL
    SELECT `user_id`
      FROM `tb_users_tags`
     WHERE 10 MEMBER OF (`user_tags`->'$');
    ```

2. Film izlemeyi seven (`10` etiketine sahip) ve 80'lerden (`2` etiketine sahip) kullanıcıların ID'sini sorgula.

    ```SQL
    SELECT `user_id`
      FROM `tb_users_tags`
     WHERE JSON_CONTAINS(`user_tags`->'$', '[2, 10]');
    ```

3. Film izlemeyi seven veya 80'lerden veya 90'lardan olan kullanıcıların ID'sini sorgula.

    ```SQL
    SELECT `user_id`
      FROM `tb_users_tags`
     WHERE JSON_OVERLAPS(user_tags->'$', '[2, 3, 10]');
    ```

> **Not**: Yukarıdaki sorguda `member of` yüklemi ve iki JSON fonksiyonu kullanıldı; `json_contains` JSON dizisinin belirtilen elemanları içerip içermediğini, `json_overlaps` ise JSON dizisinin belirtilen diziyle örtüşüp örtüşmediğini kontrol eder.

### Pencere Fonksiyonları

MySQL 8.0'dan itibaren pencere fonksiyonlarını destekler; çoğu ticari veritabanı ve bazı açık kaynak veritabanları pencere fonksiyonu desteğini çoktan sunmuştu; bazıları bunlara OLAP (çevrimiçi analiz ve işleme) fonksiyonu da der; adından da anlaşılacağı gibi istatistik ve analizle ilgilidir. Pencere fonksiyonlarını anlamanıza yardımcı olmak için önce pencere kavramından söz edelim.

Pencere, kayıtların bir kümesi olarak anlaşılabilir; pencere fonksiyonu da belirli koşulu sağlayan kayıt kümesi üzerinde çalışan özel fonksiyondur; her kayıt için bu pencere içinde fonksiyon çalıştırılır. Pencere fonksiyonları ile yukarıda anlattığımız toplama fonksiyonları kolayca karıştırılabilir; ikisinin temel farkı, toplama fonksiyonlarının birden çok kaydı tek kayda indirgemesi, pencere fonksiyonunun ise her kayıt için çalışıp kayıt sayısını değiştirmemesidir. Pencere fonksiyonu yalnızca birkaç fonksiyon değil, eksiksiz bir sözdizimidir; fonksiyon bu sözdiziminin yalnızca bir parçasıdır; temel sözdizimi aşağıdaki gibidir:

```SQL
<pencere fonksiyonu> OVER (PARTITION BY <gruplama sütun adı> ORDER BY <sıralama sütun adı>  ROWS BETWEEN ... AND ...)
<pencere fonksiyonu> OVER (PARTITION BY <gruplama sütun adı> ORDER BY <sıralama sütun adı> RANGE BETWEEN ... AND ...)
```

Yukarıdaki sözdiziminde pencere fonksiyonunun yerine şu iki tür fonksiyon konabilir:

1. Özel pencere fonksiyonları: `lead`, `lag`, `first_value`, `last_value`, `rank`, `dense_rank` ve `row_number` vb.
2. Toplama fonksiyonları: `sum`, `avg`, `max`, `min` ve `count` vb.

Aşağıda pencere fonksiyonu kullanan birkaç basit örnek verelim; doğrudan bir önceki derste oluşturduğumuz hrs veritabanını kullanalım.

Örnek 1: Aylık maaşa göre yüksekten düşüğe 4. ile 6. sıradaki çalışanların adını ve aylık maaşını sorgula.

```SQL
SELECT * 
  FROM (SELECT `ename`
             , `sal`
             , ROW_NUMBER() over (ORDER BY `sal` DESC) AS `rk`
	      FROM `tb_emp`) AS `temp`
 WHERE `rk` between 4 and 6;
```

> **Not**: Yukarıda kullanılan `row_number()` fonksiyonu her kayda bir satır numarası üretir; gerçek işte ihtiyaca göre `rank()` veya `dense_rank()` ile değiştirilebilir; üçünün farkı için resmî dokümana veya [《SQL Pencere Fonksiyonlarını Anlamak》](https://zhuanlan.zhihu.com/p/92654574) yazısına bakabilirsiniz. MySQL 8 öncesi sürümlerde benzer işlemi aşağıdaki biçimde yapabiliriz.
>
> ```SQL
> select `rank`, `ename`, `sal` from (
>        select @a:=@a+1 as `rank`, `ename`, `sal` 
>        from `tb_emp`, (select @a:=0) as t1 order by `sal` desc
> ) as `temp` where `rank` between 4 and 6;
> ```

Örnek 2: Her departmanda aylık maaşı en yüksek iki çalışanın adını ve departman adını sorgula.

```SQL
select `ename`, `sal`, `dname` 
from (
    select 
        `ename`, `sal`, `dno`,
        rank() over (partition by `dno` order by `sal` desc) as `rank`
    from `tb_emp`
) as `temp` natural join `tb_dept` where `rank`<=2;
```

> Not: MySQL 8 öncesi sürümlerde benzer işlemi aşağıdaki biçimde yapabiliriz.
>
> ```SQL
> select `ename`, `sal`, `dname` from `tb_emp` as `t1` 
> natural join `tb_dept` 
> where (
>         select count(*) from `tb_emp` as `t2` 
>         where `t1`.`dno`=`t2`.`dno` and `t2`.`sal`>`t1`.`sal` 
> )<2 order by `dno` asc, `sal` desc;
> ```
