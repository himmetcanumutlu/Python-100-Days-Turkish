> **Translated to Turkish by** himmetcanumutlu

### Yayına Hazırlık

1. Yayın öncesi kontrol çalışması.

   ```Shell
   python manage.py check --deploy
   ```

2. DEBUG'ı False yapın ve ALLOWED_HOSTS'i yapılandırın.

   ```Python
   DEBUG = False
   ALLOWED_HOSTS = ['*']
   ```

3. Güvenlikle ilgili yapılandırma.

   ```Python
   # HTTPS bağlantısını koruma süresi
   SECURE_HSTS_SECONDS = 3600
   SECURE_HSTS_INCLUDE_SUBDOMAINS = True
   SECURE_HSTS_PRELOAD = True
   
   # Güvenli bağlantıya otomatik yönlendir
   SECURE_SSL_REDIRECT = True
   
   # Tarayıcının içerik türünü kendi kafasına göre tahmin etmesini önle
   SECURE_CONTENT_TYPE_NOSNIFF = True
   
   # Siteler arası betik saldırısını önle
   SECURE_BROWSER_XSS_FILTER = True
   
   # COOKIE yalnızca HTTPS üzerinden iletilebilir
   SESSION_COOKIE_SECURE = True
   CSRF_COOKIE_SECURE = True
   
   # Tıklama kaçırma saldırısını önleme yöntemi - HTTP protokolü yanıt başlığını değiştir
   # Mevcut site <iframe> etiketiyle yüklenemez
   X_FRAME_OPTIONS = 'DENY'
   ```

4. Hassas bilgileri ortam değişkenine veya dosyaya koyun.

   ```Python
   SECRET_KEY = os.environ['SECRET_KEY']
   
   DB_USER = os.environ['DB_USER']
   DB_PASS = os.environ['DB_PASS']
   
   REDIS_AUTH = os.environ['REDIS_AUTH']
   ```

### Sunucunun Python Ortamını 3.x'e Güncelleme

> Açıklama: Önceki kurulumu temizlemek gerekirse ilgili dosya ve klasörleri silmeniz yeterlidir.

1. Alt katman bağımlılık kütüphanelerini kurma.

   ```Shell
   yum -y install zlib-devel bzip2-devel openssl-devel ncurses-devel sqlite-devel readline-devel tk-devel gdbm-devel libdb4-devel libpcap-devel xz-devel libffi-devel libxml2
   ```

2. Python kaynak kodunu indirme.

   ```Shell
   wget https://www.python.org/ftp/python/3.7.6/Python-3.7.6.tar.xz
   ```

3. İndirilen dosyayı doğrulama.

   ```Bash
   md5sum Python-3.7.6.tar.xz
   ```

4. Sıkıştırmayı ve arşivlemeyi çözme.

   ```Shell
   xz -d Python-3.7.6.tar.xz
   tar -xvf Python-3.7.6.tar
   ```

5. Kurulum öncesi yapılandırmayı çalıştırma (Makefile dosyası üretir).

   ```Shell
   cd Python-3.7.6
   ./configure --prefix=/usr/local/python37 --enable-optimizations
   ```

6. Derleme ve kurulum.

   ```Shell
   make && make install
   ```

7. PATH ortam değişkenini yapılandırma (kullanıcı veya sistem ortam değişkeni) ve etkinleştirme.

   ```Shell
   vim ~/.bash_profile
   vim /etc/profile
   ```

   ```INI
   ... yukarıdaki kod burada atlandı...
   
   export PATH=$PATH:/usr/local/python37/bin
   
   ... aşağıdaki kod burada atlandı...
   ```

    ```Shell
   source ~/.bash_profile
   source /etc/profile
    ```

8. Yumuşak bağlantı (sembolik bağlantı) kaydetme - bu adım zorunlu değildir, ancak genellikle işe yarar.

   ```Shell
   ln -s /usr/local/python37/bin/python3 /usr/bin/python3
   ```

9. Python ortamının başarıyla güncellenip güncellenmediğini test etme (Python 3 kurulumu kesinlikle mevcut Python 2'yi bozmamalıdır).

   ```Shell
   python3 --version
   python --version
   ```

### uWSGI Yapılandırması

1. uWSGI'yi kurma.

   ```Shell
   pip install uwsgi
   ```

2. uWSGI yapılandırma dosyasını değiştirme（`/root/project/conf/uwsgi.ini`）.

   ```INI
   [uwsgi]
   # Ön yolunu yapılandır
   base=/root/project
   # Proje adını yapılandır
   name=teamproject
   # Arka plan süreci
   master=true
   # Süreç sayısı
   processes=4
   # Sanal ortam
   pythonhome=%(base)/venv
   # Proje adresi
   chdir=%(base)/code/%(name)
   # Python yorumlayıcısını belirt
   pythonpath=%(pythonhome)/bin/python
   # uwsgi dosyasını belirt
   module=%(name).wsgi
   # İletişim adresi ve portu (kendi sunucunuzun IP adresi ve portu)
   socket=172.18.61.250:8000
   # Günlük dosyası adresi
   logto=%(base)/logs/uwsgi.log
   ```

   > Açıklama: Önce "iletişim adresi ve portu" satırındaki eşittirin önündeki kısmı http yapıp test edebilirsiniz; sorun yoksa tekrar socket'e çevirip Nginx aracılığıyla projenin "statik-dinamik ayırma"sını gerçekleştirin (statik kaynaklar Nginx'e, dinamik içerik uWSGI'ye verilir). Aşağıdaki şekilde uWSGI sunucusu başlatılabilir.

5. Sunucuyu başlatma.

   ```Shell
   nohup uwsgi --ini conf/uwsgi.ini &
   ```

### Nginx Yapılandırması

1. Nginx'i kurma.

    ```Shell
    yum -y install nginx
    ```

2. Küresel yapılandırma dosyasını değiştirme（`/etc/nginx/nginx.conf`）.

    ```Nginx
    # Kullanıcıyı yapılandır
    user nginx;
    # Çalışan süreç sayısı (CPU çekirdek sayısıyla aynı olması önerilir)
    worker_processes auto;
    # Hata günlüğü
    error_log /var/log/nginx/error.log;
    # Süreç dosyası
    pid /run/nginx.pid;
    # Diğer yapılandırmaları dahil et
    include /usr/share/nginx/modules/*.conf;
    # Çalışma modu (çoklamalı IO kullanımı) ve bağlantı üst sınırı
    events {
        use epoll;
        worker_connections 1024;
    }
    # HTTP sunucusuyla ilgili yapılandırma
    http {
        # Günlük biçimi
        log_format  main  '$remote_addr - $remote_user [$time_local] "$request" '
                          '$status $body_bytes_sent "$http_referer" '
                          '"$http_user_agent" "$http_x_forwarded_for"';
        # Erişim günlüğü
        access_log  /var/log/nginx/access.log  main;
        # Verimli dosya aktarım modunu etkinleştir
        sendfile            on;
        # Dosya aktarımında sendfile kullanmak performansı iyileştirir
        tcp_nopush          on;
        # Etkileşim sorununu çözmek için Nagle'ı devre dışı bırak
        tcp_nodelay         on;
        # İstemci bağlantı tutma süresi
        keepalive_timeout   30;
        types_hash_max_size 2048;
        # MIME türü yapılandırmasını dahil et
        include             /etc/nginx/mime.types;
        # Varsayılan olarak ikili akış biçimini kullan
        default_type        application/octet-stream;
        # Diğer yapılandırma dosyalarını dahil et
        include /etc/nginx/conf.d/*.conf;
        # Projenin Nginx yapılandırma dosyasını dahil et
        include /root/project/conf/*.conf;
    }
    ```

3. Yerel yapılandırma dosyasını düzenleme（`/root/project/conf/nginx.conf`）.

    ```Nginx
    server {
        listen      80;
        server_name _;
        access_log /root/project/logs/access.log;
        error_log /root/project/logs/error.log;
        location / {
            include uwsgi_params;
            uwsgi_pass 172.18.61.250:8000;
        }
        location /static/ {
            alias /root/project/stat/;
            expires 30d;
        }
    }
    server {
        listen      443;
        server_name _;
        ssl         on;
        access_log /root/project/logs/access.log;
        error_log /root/project/logs/error.log;
        ssl_certificate     /root/project/conf/cert/214915882850706.pem;
        ssl_certificate_key /root/project/conf/cert/214915882850706.key;
        ssl_session_timeout 5m;
        ssl_ciphers ECDHE-RSA-AES128-GCM-SHA256:ECDHE:ECDH:AES:HIGH:!NULL:!aNULL:!MD5:!ADH:!RC4;
        ssl_protocols TLSv1 TLSv1.1 TLSv1.2;
        ssl_prefer_server_ciphers on;
        location / {
            include uwsgi_params;
            uwsgi_pass 172.18.61.250:8000;
        }
        location /static/ {
            alias /root/project/static/;
            expires 30d;
        }
    }
    ```

    Bu noktada Nginx'i başlatıp uygulamamıza erişebiliriz; HTTP ve HTTPS'te sorun yoktur; Nginx zaten çalışıyorsa yapılandırma dosyasını değiştirdikten sonra aşağıdaki komutla Nginx'i yeniden başlatabiliriz.

4. Nginx sunucusunu yeniden başlatma.

    ```Shell
    nginx -s reload
    ```

    veya

    ```Shell
    systemctl restart nginx
    ```

> Açıklama: Django projesinde `python manage.py collectstatic` komutuyla statik kaynaklar belirtilen dizine toplanabilir; bunu yapmak için projenin `settings.py` yapılandırma dosyasına yalnızca `STATIC_ROOT` yapılandırmasını eklemeniz yeterlidir.

#### Yük Dengeleme Yapılandırması

Aşağıdaki yapılandırmada Nginx ile yük dengeleme gerçekleştirip diğer üç Nginx sunucusu (Docker ile oluşturulmuş) için ters vekil hizmeti sağlıyoruz.

```Shell
docker run -d -p 801:80 --name nginx1 nginx:latest
docker run -d -p 802:80 --name nginx2 nginx:latest
docker run -d -p 803:80 --name nginx3 nginx:latest
```

```Nginx
user root;
worker_processes auto;
error_log /var/log/nginx/error.log;
pid /run/nginx.pid;

include /usr/share/nginx/modules/*.conf;

events {
    worker_connections 1024;
}

# HTTP servisi için yük dengeleme yapılandır
http {
	upstream xx {
		server 192.168.1.100 weight=2;
		server 192.168.1.101 weight=1;
		server 192.168.1.102 weight=1;
    }

	server {
		listen       80 default_server;
		listen       [::]:80 default_server;
		listen       443 ssl;
		listen       [::]:443 ssl;

        ssl on;
		access_log /root/project/logs/access.log;
		error_log /root/project/logs/error.log;
		ssl_certificate /root/project/conf/cert/214915882850706.pem;
		ssl_certificate_key /root/project/conf/cert/214915882850706.key;
		ssl_session_timeout 5m;
		ssl_ciphers ECDHE-RSA-AES128-GCM-SHA256:ECDHE:ECDH:AES:HIGH:!NULL:!aNULL:!MD5:!ADH:!RC4;
		ssl_protocols TLSv1 TLSv1.1 TLSv1.2;
		ssl_prefer_server_ciphers on;

		location / {
			proxy_set_header Host $host;
			proxy_set_header X-Forwarded-For $remote_addr;
			# proxy_set_header X-Real-IP $remote_addr;
			# proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
			proxy_buffering off;
			proxy_pass http://fangtx;
		}
	}
}
```

> Açıklama: Nginx yük dengeleme yapılandırırken varsayılan olarak WRR (ağırlıklı round-robin algoritması) kullanır; ayrıca ip_hash, fair (upstream_fair modülünün kurulmasını gerektirir) ve url_hash algoritmalarını destekler. Ayrıca upstream modülünü yapılandırırken sunucunun durum değeri belirtilebilir: backup (yedek makine, diğer sunucular kullanılamaz olduğunda istek bu makineye dağıtılır), down, fail_timeout (istek başarısızlığı max_fails'e ulaştıktan sonra servisi duraklatma süresi), max_fails (izin verilen istek başarısızlık sayısı) ve weight (round-robin ağırlığı).

### Keepalived

Nginx ile yük dengeleme yapılandırırken yük dengeleme sunucusunun çökme durumu dikkate alınmalıdır. Bunun için yük dengeleme ana makinesi ile yedek makinesinin sıcak değişimini gerçekleştirmek üzere Keepalived kullanılabilir; böylece sistemin yüksek erişilebilirliği sağlanır. Keepalived'in yapılandırması görece karmaşıktır; genellikle işletmeden sorumlu kişiler tarafından yapılandırılır; temel bir yapılandırma için [《Keepalived Yapılandırması ve Kullanımı》](https://www.jianshu.com/p/dd93bc6d45f5) sayfasına bakılabilir.


   ```
   server-id=1

   expire_logs_days=30
   max_binlog_size=256M
   symbolic-links=0
   ```

```Python
DATABASE_ROUTERS = [
    # Diğer yapılandırmalar burada atlandı
    'common.routers.MasterSlaveRouter',
]
```

```Python
class MasterSlaveRouter(object):
    """Ana-uydu çoğaltma yönlendirmesi"""

    @staticmethod
    def db_for_read(model, **hints):
        """
        Attempts to read auth models go to auth_db.
        """
        return random.choice(('slave1', 'slave2', 'slave3'))

    @staticmethod
    def db_for_write(model, **hints):
        """
        Attempts to write auth models go to auth_db.
        """
        return 'default'

    @staticmethod
    def allow_relation(obj1, obj2, **hints):
        """
        Allow relations if a model in the auth app is involved.
        """
        return None

    @staticmethod
    def allow_migrate(db, app_label, model_name=None, **hints):
        """
        Make sure the auth app only appears in the 'auth_db'
        database.
        """
        return True
```

### Docker

Aslında proje yayına alınırken en zahmetli iş, yazılım çalışma ortamını yapılandırmaktır; ortam farklılıkları yazılımın kurulumuna ve dağıtımına pek çok sorun getirir; Docker tam da bu sorunu çözer. Docker hakkında önceki dokümanlarda anlatmıştık; şimdi Docker bilgisine bazı gerekli eklemeler yapıyoruz.

1. İmaj dosyası oluşturma.

    Konteyneri imaj olarak kaydetme:

   ```Shell
   docker commit -m "..." -a "jackfrued" <container-name> jackfrued/<image-name>
   ```

   Dockerfile ile imaj oluşturma:

   ```Dockerfile
   # Temel imaj dosyasını belirt
   FROM centos:latest
   
   # Bakımcı bilgisini belirt
   MAINTAINER jackfrued
   
   # Komut çalıştır
   RUN yum -y install gcc
   RUN cd ~
   RUN mkdir -p project/code
   RUN mkdir -p project/logs
   
   # Dosya kopyala
   COPY ...
   
   # Portu dışa aç
   EXPOSE ...
   
   # Konteyner başlatılırken komut çalıştır
   CMD ~/init.sh
   ```

   ```Shell
   docker build -t jackfrued/<image-name> .
   ```

2. İmajın içe ve dışa aktarılması.

   ```Shell
   docker save -o <file-name>.tar <image-name>:<version>
   docker load -i <file-name>.tar
   ```

3. DockerHub sunucusuna itme.

   ```Shell
   docker tag <image-name>:<version> jackfrued/<name>
   docker login
   docker push jackfrued/<name>
   ```

4. Konteynerler arası iletişim.

   ```Shell
   docker run --link <container-name>:<alias-name>
   ```


Eğer projenin dağıtımını Docker'da tamamlayabilir ve dağıtılan konteynerin tamamını imaj dosyası olarak paketleyip dağıtır ve kurarsak, projenin birden çok düğümde dağıtılmasında karşılaşılabilecek sorunlar çözülür; üstelik tüm dağıtım çok kısa sürede tamamlanabilir.

### Supervisor

[Supervisor](https://github.com/Supervisor/supervisor), Python ile yazılmış bir süreç yönetim aracıdır; Unix benzeri sistemlerde süreçleri başlatma, yeniden başlatma (programı otomatik yeniden başlatma) ve kapatma işlemleri için çok rahat kullanılabilir; şu anda Supervisor henüz Python 3 desteği sunmaz; Supervisor'ı Python 2 ile kurup çalıştırabilir, ardından Supervisor ile Python 3 programlarını yönetebilirsiniz.

> **İpucu**: Supervisor'a benzer işleve sahip Circus adlı bir araç daha vardır; Python 3'ü destekler.

1. Supervisor'ı kurma.

   ```Shell
   virtualenv -p /usr/bin/python venv
   source venv/bin/activate
   pip install supervisor
   ```
   
2. Supervisor'ın yapılandırma dosyasını görüntüleme.

    ```Shell
    vim /etc/supervisord.conf
    ```

    ```INI
    ; Yukarıdaki kod burada atlandı
    ; The [include] section can just contain the "files" setting.  This
    ; setting can list multiple files (separated by whitespace or
    ; newlines).  It can also contain wildcards.  The filenames are
    ; interpreted as relative to this file.  Included files *cannot*
    ; include files themselves.
    [include]
    files = supervisord.d/*.ini
    ```

    Görüldüğü gibi özel yönetim yapılandırma kodu `/etc/supervisord.d` dizinine konulabilir ve dosya adının son eki `ini` olmalıdır.

3. Kendi yapılandırma dosyanızı `fangtx.ini` yazıp `/etc/supervisord.d` dizinine koyma.

   ```INI
   [program:project]
   command=uwsgi --ini /root/project/conf/uwsgi.ini
   stopsignal=QUIT
   autostart=true
   autorestart=true
   redirect_stderr=true
   
   [program:celery]
   ; Set full path to celery program if using virtualenv
   command=/root/project/venv/bin/celery -A fangtx worker
   user=root
   numprocs=1
   stdout_logfile=/var/log/supervisor/celery.log
   stderr_logfile=/var/log/supervisor/celery_error.log
   autostart=true
   autorestart=true
   startsecs=10
   
   ; Need to wait for currently executing tasks to finish at shutdown.
   ; Increase this if you have very long running tasks.
   ;stopwaitsecs = 600
   
   ; When resorting to send SIGKILL to the program to terminate it
   ; send SIGKILL to its whole process group instead,
   ; taking care of its children as well.
   killasgroup=true
   ; Set Celery priority higher than default (999)
   ; so, if rabbitmq is supervised, it will start first.
   priority=1000
   ```

4. Supervisor'ı başlatma.

   ```Shell
   supervisorctl -c /etc/supervisord.conf
   ```
